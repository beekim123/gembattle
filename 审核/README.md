# 审核

请别的 AI 审设计稿和原型。每个审核者一个目录，结果分开放，方便对比。

## 目录

```
审核/
├── README.md          这份：规矩，加上每轮审了什么、怎么处理的
├── 审核提示词.md      交给审核者的整段提示词
├── neon/              Neon 的审核结果
├── claude/            Claude 的审核结果（审核的那个 Claude，不是写设计稿的这个）
└── <别的审核者>/      以后加谁就建一个目录，名字用小写英文
```

## 文件名

`审核/<审核者>/<日期>-<审的是什么>.md`

例子：`审核/neon/2026-11-24-设计稿第1版.md`

- 同一个审核者审第二轮，就再加一个新文件，不覆盖旧的。
- 审核者只往自己的目录里写，不改 `设计/` 里的东西。
- 一个审核者如果给了好几份（比如先审一遍，又补充一遍），都放进他自己的目录，文件名后面加「-补充」。

## 怎么用

1. 把 `审核提示词.md` 里「提示词」那一段整段贴给审核者。如果他读不到这个文件夹，就把 `设计/设计.md` 的全文一起贴过去。
   - **审核者那边如果有联网搜索、深度研究（Deep Research）一类的开关，先打开。** 提示词要求它先查同类游戏和设计资料，每条意见写依据，免得它凭空乱设计。
2. 他交回来的东西，存成上面那种文件名，放进他的目录。
3. 几家都审完以后，写设计稿的人（谁接手谁写）把各家意见汇总成一份，放在 `审核/汇总-<日期>.md`（同一天有两轮，后面加「-第几轮」）：
   - 列出每条意见：谁提的，同意、不同意还是要问用户，理由是什么；
   - 意见的分量看依据：
     - 有出处的，抽查几条出处是不是真的、说没说过那个意思；
     - 只标「我的判断」的，看推理和算数站不站得住；
     - 两家说法冲突时，把双方的依据都列出来，交给用户定；
   - 要改设计的，先跟用户对，用户点头了再改 `设计/设计.md`。
4. 改完以后，在下面「每一轮」的表里记一行。
