# 原型

**现在**：neon 做完了阶段 0 和阶段 1 前半段（`原型/neon/`），只做了逻辑，画面是调试面板。用户决定**剩下的交给 claude 接着做**，就在 `原型/neon/` 里接着做（提交信息写 `[claude]`），先做布局。检查记录：`检查-neon-阶段0到1前半.md`。接手提示词：`提示词-接手neon.md`，一个窗口同时做布局和阶段 1 后半段。`原型/claude/` 里只有启动脚本，不再往下做。

以后可能让几种 AI 各照 `设计/设计.md` 做一份原型，横向对比。每份放在自己的目录里，互不相干。

```

├── 提示词-阶段0.md    交给做原型的 AI 的阶段 0 提示词

├── <别的 AI>/         以后加谁就建一个目录，名字用小写英文
└── ...
```

## 每份原型的规矩

1. **自己能跑**：每份单独一个目录，有自己的启动方法。原型不用 Electron（用户定的），在浏览器里跑：要有一个启动脚本，Mac 上双击它，开本地小服务、自动用浏览器打开就能玩（做法见 `原型/claude/README.md`）。不依赖别的原型目录，也不依赖 `旧/`。
2. **照设计稿的第 10 节分模块**：`modules/`、`app/`、`tools/` 都在这份原型自己的目录里。
3. **自带三份文档**：
   - `README.md`：怎么跑、怎么测、目录说明；
   - `进度.md`：做到哪个阶段、下一步、碰到的坑，跟根目录的 `进度.md` 一个写法；
   - `偏离.md`：哪里跟设计稿不一样、为什么。没有偏离就写「没有」。
4. **只改自己的目录**：做原型的 AI 不改 `审核/` 和别的原型。觉得设计有问题，写进自己的 `偏离.md` 或者告诉用户。`设计/设计.md` 只在用户拍板以后改，而且跟原型在同一次提交里一起改（规矩见根目录 `CLAUDE.md` 第 3 节「设计稿和原型要对得上」）。
5. **按阶段走**：照设计稿 10.4 的阶段 0 → 5 做，每做完一个阶段在自己的 `进度.md` 里记一行，本地 git 提交一次，提交信息开头写目录名，比如 `[claude] 阶段 1 战斗`。不推远端。
6. **共同的硬约束**见根目录 `CLAUDE.md`：浏览器里跑的 HTML + 原生 JS + Canvas 2D、色块、不取名、界面中文、用词避开套路字。做法跟以后的 Electron 正式版一样，搬过去只加壳（设计稿第 10 节）。

## 横向对比怎么做

几份原型做到同一个阶段以后，在 `对比记录.md` 里记一轮：

| 看什么 | 怎么看 |
|---|---|
| 好不好玩 | 用户自己玩，按设计稿第 2 节的三条支柱打分 |
| 照没照设计 | 对着设计稿逐节看，加上它的 `偏离.md` |
| 解耦 | 每个模块能不能单独跑 demo、单独跑单测；有没有越过 `index.js` 伸手进别的模块 |
| 代码 | 好不好读、好不好改，加一种功能牌要动几个文件 |
| 稳不稳 | 截图试玩工具跑一圈有没有报错，单测全不全 |

对比以后，可以挑一份接着做，也可以把几份里好的做法挑出来，合进一份。
