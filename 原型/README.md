# 原型

**现在还没开工**：等审核汇总、用户确认设计以后，用户下指令才动手。

以后可能让几种 AI 各照 `设计/设计.md` 做一份原型，横向对比。每份放在自己的目录里，互不相干。

## 目录

```
原型/
├── README.md          这份：规矩
├── 对比记录.md        几份原型做出来以后再建：同一阶段谁做得怎么样
├── claude/            Claude 做的那份
├── <别的 AI>/         以后加谁就建一个目录，名字用小写英文
└── ...
```

## 每份原型的规矩

1. **自己能跑**：每份有自己的 `package.json`、启动方法和依赖，在自己的目录里 `npm install`、`npm start` 就能跑，不依赖别的原型目录，也不依赖 `旧/`。
2. **照设计稿的第 10 节分模块**：`modules/`、`app/`、`tools/` 都在这份原型自己的目录里。
3. **自带三份文档**：
   - `README.md`：怎么跑、怎么测、目录说明；
   - `进度.md`：做到哪个阶段、下一步、碰到的坑，跟根目录的 `进度.md` 一个写法；
   - `偏离.md`：哪里跟设计稿不一样、为什么。没有偏离就写「没有」。
4. **只改自己的目录**：做原型的 AI 不改 `设计/`、`审核/` 和别的原型。觉得设计有问题，写进自己的 `偏离.md` 或者告诉用户。
5. **按阶段走**：照设计稿 10.4 的阶段 0 → 5 做，每做完一个阶段在自己的 `进度.md` 里记一行，本地 git 提交一次，提交信息开头写目录名，比如 `[claude] 阶段 1 战斗`。不推远端。
6. **共同的硬约束**见根目录 `CLAUDE.md`：Electron + 原生 JS + Canvas 2D、色块、不取名、界面中文、用词避开套路字。

## 横向对比怎么做

几份原型做到同一个阶段以后，在 `对比记录.md` 里记一轮：

| 看什么 | 怎么看 |
|---|---|
| 好不好玩 | 用户自己玩，按设计稿第 2 节的三条支柱打分 |
| 照没照设计 | 对着设计稿逐节看，加上它的 `偏离.md` |
| 解耦 | 每个模块能不能单独跑 demo、单独跑单测；有没有越过 `index.js` 伸手进别的模块 |
| 代码 | 好不好读、好不好改，加一种功能牌要动几个文件 |
| 稳不稳 | 截图试玩工具跑一圈有没有报错，单测全不全 |

对比以后，可以挑一份接着做，也可以把几份里好的做法挑出来，合进一份。
