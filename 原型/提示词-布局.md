# 提示词 A：布局窗口（跟「阶段 1 后半段窗口」同时开）

用法：开一个新窗口，把下面「提示词」那一段整段贴进去。另一个窗口贴 `提示词-阶段1后半.md`。两个窗口同时在 `原型/neon/` 里干活，分工见提示词里的「两个窗口怎么分」。

---

## 提示词

你接手 code00 的原型，**只管画面和布局**。neon 已经做完阶段 0 和阶段 1 前半段，在 `原型/neon/` 里，规则和工具都扎实，但它只做了逻辑，**画面是一张调试面板，没有游戏的布局**。用户说：从现在开始要考虑布局和好不好看，**这就是以后游戏里的布局**。

同时还有另一个窗口在做「阶段 1 后半段」（加成、队友的逻辑）。你们俩在同一个目录里干活，按下面分工，互不踩。

**先读这些**
1. `CLAUDE.md`：项目的全部规矩，照着做（回复用中文、一步一提交、不推远端、每次回复报还剩多少设计没定……）。
2. `进度.md` 开头的「现在」。
3. `原型/检查-neon-阶段0到1前半.md`：neon 的东西检查过了，里面列了画面上要改的。
4. `原型/README.md`，`原型/neon/` 里的 `README.md`、`进度.md`、`偏离.md`。
5. `设计/设计.md`：第 2 节（三条设计支柱，特别是「快、炸、看得懂」）、第 5 节（战斗）、第 7 节（探索是俯视的空地）、第 10 节（工程）。
6. 以后的正式美术是俯视的像素堆叠，可以看 `美术/教程-像素堆叠AI制作方案/README.md` 了解长什么样。现在先用色块占位。只看，不改。
- **不要读** `旧/` 目录和上一级的 `../异能卡牌/`。

**两个窗口怎么分**
- **你（布局窗口）改**：`modules/battle-view/`、`modules/ui/`、`modules/render/`、`app/`、`tools/shot.js`，新建 `设计/界面.md`。
- **另一个窗口（阶段 1 后半段）改**：`modules/shared/`、`modules/battle-rules/`、`modules/content/`、`tools/sim.js`。这几个你**只读不改**。需要它们加东西（比如快照里多一个字段），写进 `原型/neon/进度.md` 里你那一节的「要另一个窗口做的」，告诉用户，由那边加。
- 进度：`原型/neon/进度.md` 和根目录 `进度.md` 的「现在」里，各分一小节「布局窗口」「阶段 1 后半段窗口」。**只改你那一小节**；改之前先重新读一遍文件，别把另一个窗口刚写的盖掉。「记录」只往末尾加一行。
- 提交：只提交你改的文件，用 `git commit -m "..." -- <文件或目录>` 这种写法，只提交列出来的路径，**不要用 `git add -A`、`git commit -a`**。`美术/` 里有用户别的没提交的东西，别碰。提交信息开头写 `[claude 布局]`。**不推远端。**
- `npm test` 里有另一个窗口的测试。你改完跑一遍，挂了的要是不在你的文件里，告诉用户，别去改它的。

**第一步：修小毛病**（检查记录第 4 条）
- 打出以后飘的伤害数字，别压在怪的名字和信息上；
- 蓝宝石牌上的蓝点看不见：宝石点要在任何颜色的牌面上都看得清；
- 功能牌名字里的换行符是 `content` 里写的，你别改那边。在画面这边按宽度自动换行；把「名字里别写换行符」记进「要另一个窗口做的」。

**第二步：定布局**（最重要，要用户拍板）
1. **先定整个游戏的画面框架**，不只是战斗。以后的探索（俯视空地）、大厅，都要用同一套：
   - 逻辑分辨率（现在是 960×540，16:9）。要不要换成别的，给理由；
   - 顶上一条状态栏放什么：心、金币、任务、宝石等级、集色……哪些常驻，哪些只在战斗里有；
   - 字号几档、间距、配色（深色底；七种宝石色在牌面和底色上都要看得清；暴击和破盾要显眼）；
   - 这些都定在一处：配色和字号放 `modules/ui/` 的主题里，区域划分放各画面模块自己的 `layout.js`。画面代码里不出现写死的坐标。
2. **战斗画面做 2~3 个真不一样的布局**，用色块和假数据画出来（可以用 `battle-view` 的 demo 页），截图给用户看。每个写清优点、缺点，说你倾向哪个，用户挑。要考虑：
   - 像游戏，不像工具：怪要大、要在视线中心；心、血、盾、倒计时、怪下一手要干什么，一眼看得到；说明文字少，细节放鼠标悬停的提示里；
   - 手牌、排好的链、打出去的伤害，三样的位置关系，让「排链 → 打出 → 数字炸开」这一下顺眼又爽；
   - 一群怪（2~4 只）、看门的 3 条血、上万发的大链，放进去都不乱；
   - **给加成和队友留好位子**：另一个窗口在做，做完以后战斗里要显示这一趟拿到的加成（可能好几个）、带的队友（1~3 个）和队友出手；
   - 给以后的像素堆叠美术留好位子：怪、主角、队友现在是色块，但大小和摆放就按以后要放立绘的位置来。主角和队友在战斗里要不要出现、放哪，一起提出来让用户定；
   - 浏览器窗口大小不一样（比如 800×600、全屏）也不能乱。
3. 用户挑定以后，把定下来的写进 `设计/界面.md`（新建）：画面框架、战斗布局、配色字号，附截图。以后做探索、大厅照这份来。`设计/设计.md` 不用改，等写设计稿的 claude 加指向。

**第三步：照定下来的布局重做战斗画面**
- 改 `modules/battle-view/`。规则不归你管，一行不动。
- 选仗台和那些开关是试玩工具：收进一个「调试」面板（比如按一个键或点角上的小按钮才出来），不占游戏画面。用户试玩时还要能切这些开关。
- 用 `npm run shot` 截全套图，自己逐张看，再给用户试玩。

**第四步：接上加成和队友**
- 等另一个窗口把加成、队友的逻辑做完（看 `原型/neon/进度.md` 里它那一节），在新布局里把它们显示出来：拿到的加成、带的队友、队友出手的演出、算式里队友加的那一份。
- 那边没做完，就先用假数据把位子做好，等它做完再接。

**交回来的时候说清楚**：做了什么、怎么打开、截图在哪、用户拍板了哪些、要另一个窗口做的有哪些、哪里跟设计稿不一样。
