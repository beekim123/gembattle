# 性能与流畅度（claude，2026-11-23）

用户要的：动画像 p5.js 那样流畅；画质清晰；同屏能多放几只、帧率稳。用户自己测，原来同屏 3 只就到 120 帧的极限了。

这份记下：原来慢在哪、改了什么、实测数字、怎么复测、还没做的。

## 1. 结论

- **帧率和同屏数量：达到了。** 2560×1440、林地、巡游中，同屏 36 只每帧 4.7ms（约 210fps，p95 5.6ms），24 只 3.0ms。原来 6 只就 9.9ms、24 只 55ms。
- **画面清晰、动起来不跳：渲染这一层达到了。** 画面放大倍数取整数，部件按屏幕像素摆放，大部件的角度档位变细，逻辑按固定小步走。
- **「身体是一整张皮」那种 p5.js 式的生物感：还没有。** 现在链式身体（蛇、十身鱼、腿、尾）还是一节一颗拼起来的，主躯干是一整块刚体。这要逐只改，见第 6 节。

p5.js 本身也是画在 Canvas 2D（或 WebGL）上，它不会让东西变快。p5.js 那种程序化动画看着顺，是因为每帧要做的事少、位置和角度是连续的。工坊现在每帧的活也很少（只贴烘焙好的图），所以帧率上不输它。

## 2. 实测

### 新旧对比（同一台机器，2560×1440，同样的放大倍数，林地，巡游）

| 同屏 | 原来每帧 | 现在每帧 | 现在约合 fps |
|---|---|---|---|
| 1 | 1.32ms | 0.71ms | 1400 |
| 3 | 2.16ms | 0.77ms | 1300 |
| 6 | 9.93ms | 1.10ms | 900 |
| 12 | 16.12ms | 1.60ms | 620 |
| 24 | 55.07ms | 3.00ms | 330 |
| 36 | — | 4.74ms | 210 |

一直转视角的时候（最费缓存）：现在 3 只 0.84ms、12 只 2.08ms；原来 3 只 2.51ms。

「每帧」是不等屏幕刷新、连着跑时一帧的真实耗时（CPU + GPU）。比屏幕刷新间隔（120Hz 是 8.33ms）小就是稳满帧，差得越多余量越大。

### 怎么测的

- 工坊右栏「跑一轮压测」，或者网址加 `?bench=1`，或者控制台 `PixelWorkshop.Bench.suite()`（代码在 `tools/bench.js`）；
- 在离屏画布上连续跑 N 帧「逻辑 + 渲染」。每帧把画布 1 个像素拷到 1×1 小画布上，逼浏览器把这一帧真的交给 GPU；最后读一次小画布，等 GPU 干完。总时长 ÷ 帧数；
- **别每帧 `getImageData` 读主画布**：Chrome 会把主画布降成 CPU 渲染，数字全不准。一开始我就是被这个骗了。

### 预览台上的性能浮层

预览台左上角有一块半透明的浮层（P 键：折叠 → 展开 → 隐藏，点标题也能折叠 / 展开，代码在 `app/perf-hud.js`）：

- **折叠**：帧率、每帧用了多少 / 预算多少、**短板是谁**，下面一条最近 180 帧的帧间隔小图（浅色是帧间隔，深色是主线程时间，横线是预算，红的是掉帧）；
- **展开**：短板的原因；帧（刷新率、帧间隔中位 / p95 / 最慢、掉帧次数）；每帧开销（逻辑、渲染指令、烘焙、GPU、满负荷一帧、余量），每项一根「占预算多少」的条；贴图（图集用量、淘汰、救回、丢失）；画面（同屏、部件数、绘制次数、画布尺寸、像素倍数、渲染方式）。

GPU 耗时 Canvas 2D 读不到，而且单读一次「等 GPU 画完」本身就要 1~5ms 来回，所以不能每帧抽。浮层的做法：场景一变（同屏数量、生境、渲染方式、缩放、画布大小），等 0.9 秒缓存热了，在原画面上不等刷新连着画 6~40 帧、最后只等一次，扣掉一次来回的延迟，得出「满负荷一帧」。这个数明显比主线程大，就是 GPU 在拖后腿。测的时候画面停几十毫秒，那一下不算进统计。展开后「满负荷」那行有「重测」。

浮层跟压测对得上：单只史莱姆满负荷 0.70ms（压测 0.71），24 只 3.07ms（压测 3.00）。

**窗口在后台、被挡住、省电模式、录屏时，浏览器会给页面限帧**，这时浮层会直接写「浏览器限帧」，别拿那时的数字下结论。

## 3. 原来慢在哪

1. **Chrome 的贴图断崖**：一帧里引用的贴图总量超过 32MB 左右，GPU 耗时会突然涨 7~35 倍。跟主画布多大无关，只看这一帧用到的贴图有多少。原来的缓存按张数封顶（3600 张），图越做越大，3 只怪就能把一帧的贴图撑过线。这是「3 只就到极限」的主要原因。
2. **大图集页**：试过 2048² 的大页，一页 16MB，用到几页就过线，更糟。
3. **每只怪单独一张离屏画布描边**：每只每帧先拼到自己的画布、描边、再贴回去，同屏越多越慢。
4. **整屏天空贴图**：每帧贴一张整屏大小的天空，平白占掉十几 MB 的「本帧贴图」。
5. **角度一律 3° 一档、位置按烘焙像素取整、最后放大倍数不是整数**：大部件转起来一格一格跳，移动有台阶，画面略糊。
6. **逻辑步长跟着帧率走**：60Hz 和 120Hz 屏上弹簧手感不一样，掉帧时像慢动作。

## 4. 改了什么（都在 `core/renderer.js`，生物脚本基本不用动）

| 改动 | 为什么 |
|---|---|
| 烘焙图集：512² 小页，总量封顶 28MB（右栏可调），满了淘汰最久没用的页；正在用的条目当场重画（`rescued`），不丢帧（`lost` 一直是 0） | 躲开 32MB 断崖；页小，淘汰时丢的热数据少 |
| 每帧两步走：先把所有部件的贴图解析 / 烘焙好，再统一画 | 画的时候图集不再被改，浏览器不用额外复制 |
| 描边改成「先把所有部件外扩一圈的剪影画出来，再按深度画本体」，不再每只一张离屏画布 | 一圈剪影的并集就是整体外轮廓，效果跟原来一样，开销跟同屏数量线性 |
| 角度档位按部件大小自适应（1.5°~7.5°，部件边缘每档最多挪 1.75 个烘焙像素） | 大部件转起来不跳，小部件省缓存 |
| 左右对称的部件只烘 0~180°，另一半水平翻转着画 | 缓存减半 |
| 烘焙按体素真正占的范围裁紧 | 体素盒常留很多空边 |
| 画面放大倍数取整数（1 个美术像素 = 整数个屏幕像素），部件位置按屏幕像素取整 | 不糊；移动精度从「烘焙像素」细到「屏幕像素」 |
| 浸水改成「染水色」（不透明，分 3 档），设计上的半透明单独用 `opacity` | 原来水下半透明部件互相叠出深浅斑，描边也跟着半透明 |
| 天空画在 1/8 大小的小画布上再放大贴 | 不占整屏贴图，也省了每帧画渐变 |
| 自亮柔化只处理有光的那一块；整帧没光就跳过 | 原来每帧整屏模糊一次 |
| 每帧烘焙预算 2.5ms，超了先借相邻角度顶一帧 | 转视角时不卡 |
| 换色时 `recolorAsset` 给资产加版本号，缓存自动作废 | 不用手动清缓存 |
| 同种怪共用部件和缓存（`PW.Assets.spawn` 传模板） | 同屏 30 只史莱姆只占一只的贴图 |
| 逻辑按不超过 1/120 秒一步走（`app/app.js` 主循环） | 任何刷新率下手感一样，掉帧时不变慢动作 |

## 5. 以前那份外部审核建议的采纳情况

上午有一份 `审核建议-claude-2026-11-23.md`（用户已经删了，原文在 `../像素堆叠生物工坊-改前备份-2026-11-23.tar.gz` 里）。各条到这次为止：

| 条目 | 内容 | 情况 |
|---|---|---|
| A1 | 角度 3° 一档太粗 | **做了**：按部件大小自适应 1.5°~7.5° |
| A2 | 部件位置按烘焙像素取整 | **做了**：按屏幕像素摆放 |
| A3 | 呼吸 / 压扁用最近邻拉伸整张图 | **没改**：渲染器还支持 `scaleX / scaleY`。经验文档已经要求常态别用；要彻底解决得把会形变的部件改成实时逐层画，跟 B 一起做 |
| A4 | 最后的放大倍数不是整数 | **做了** |
| B | 链式身体和腿是一串珠子 | 没做，要逐只改（第 6 节） |
| C | 主躯干一整块刚体，没有脊柱和头颈 | 没做，要逐只改 |
| D1 | 游动波应该从头传到尾 | 没做 |
| D2 | 没有固定步长 | **做了** |
| D3 | 走路时身体不起伏 | 没做 |
| D4 | 习性切换是硬开关 | 没做 |
| E | 水下半透明叠出珠子斑 | **做了**：染水色 + `opacity` 分开 |
| F | 体量变大以后缓存撑爆 | **做了**：按字节封顶的图集 + 淘汰重画 |

## 6. 还没做的（生物感，要逐只改）

- **B 连续的身体**：蛇身、鱼身、尾、触手、腿不再拼烘焙好的小球，每帧按关节用 `VoxelModel.paintCapsule` 在一张复用的小体素网格里画一根连续的身体，再实时逐层画。建议先拿魔蛇（`creatures/snake.js`）试，跟现在的并排比。注意每帧调用的建模函数要改成复用缓冲，不然垃圾回收会卡。
- **C 脊柱和头颈**：四足拆胸、腰、胯 3 节加颈和头，头用弹簧追「看的目标」；肚嘴巨兽的嘴拆上下唇用弹簧开合。
- **D1** 游动时把摆动加在头上、让约束把波传下去；待机时保留逐节正弦，按速度渐变。
- **D3** 身体高度跟步态周期起伏，对角腿交替时轻微横滚。
- **D4** 所有布尔开关先过弹簧或 `smoothstep` 再驱动动作。

做了 B、C 以后，链式身体和躯干改成实时画，不占角度缓存，贴图压力还会再降。

## 7. 改渲染器以后要守的

- 一帧引用的贴图别超过 32MB：图集预算别调过 32MB，别新开整屏大小的离屏画布。浮层「贴图」那行快满会变黄、过线会报短板；
- 别每帧 `getImageData` 读主画布；
- 改完跑一次压测，跟第 2 节的表比。
