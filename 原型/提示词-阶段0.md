# 提示词：阶段 0 搭架子

用法：把下面「提示词」那一段整段贴给做原型的 AI。`<你的名字>` 换成它的目录名，比如 neon。

---

## 提示词

你要给一个卡牌肉鸽游戏做原型的**阶段 0：搭架子**。游戏暂叫 code00。这一步只搭架子，不写玩法。

**先读这些**
1. `CLAUDE.md`（跟 `AGENTS.md` 一样）：项目的全部规矩。
2. `设计/设计.md`：
   - 第 1 节「硬约束」；
   - 第 10 节「工程」整节，尤其是 10.1 模块、10.2 解耦的规矩、10.3 模块之间传的东西、10.4 做的顺序（阶段 0 那几条）；
   - 第 5.9 节「时机」和「动作」，第 5.2 节的色环和七种颜色：`shared/` 里要放它们的名字。
3. `原型/README.md`：做原型的规矩。
4. `原型/claude/README.md`：已经做好的启动脚本和本地小服务，可以照着做，也可以直接复制过去用。
- 设计稿是第 3 版，用户已经整份点过头了。想知道为什么这么定，可以翻 `审核/` 里的两份汇总，不读也行。
- **不要读** `旧/` 目录和上一级的 `../异能卡牌/`，那是作废的旧做法。

**硬约束**
- **原型不用 Electron**（用户定的）：全用原生 JS 写在 HTML 里，在浏览器里跑，Canvas 2D 画。不用游戏引擎、3D 库、打包工具。
- 做法要跟以后的 Electron 正式版一样：一样的模块、一样的目录、一样的约定、只在 `app/` 里组装。以后搬过去只加一个壳，模块不改。
- 用浏览器自带的 ES 模块（`import` / `export`），从本地小服务打开（设计稿 10.2 第 7 条）。
- 画面一律用简单色块。界面中文。什么都不取名。
- 用词避开灯、烬、影、夜、魂、噬、幽、渊、星、光这类字，也不用「守×者」「×之×」这类格式。
- 解耦（用户定的）：每个模块一个单独目录，对外只有一个 `index.js`；能单独跑、单独测；模块之间只靠 `shared/` 里约定好的数据来往；只在 `app/` 里组装。规则模块不碰 `document`、`canvas`，单测要能直接在 node 里跑。
- 尽量不装依赖。真要装，写进你的 `README.md` 和 `偏离.md`，说清为什么。

**阶段 0 要做的**（全部放在 `原型/<你的名字>/` 里）
1. **启动**：Mac 上双击 `启动.command` 能开本地小服务、自动用浏览器打开；`npm start` 也行。可以照搬 `原型/claude/` 的 `启动.command`、`package.json`、`tools/serve.js`。
2. **`modules/shared/`**：
   - 战斗要用的四样约定（10.3）：动作表、开战包、战斗的快照 / 预览 / 演出事件、战斗结果。第 3 版补的字段都要有：心的上限、随机数种子、手里每张牌能不能接、牌堆每色剩几张、被遮住的牌、打完以后的宝石等级、打死了哪些怪、动作的「持续多久」和「会不会再触发别的」。
   - 用 JS 写成数据结构和说明（比如 JSDoc），再配一个检查函数，能判断一份数据合不合约定。
   - 色环和七种颜色、时机和动作的名字（5.9）、能指定种子的随机数。
   - **不放玩法**：不写怎么接链、怎么算伤害，那是阶段 1 `battle-rules` 的事。
3. **`modules/render/blocks/`**：画色块的接口，比如方块、圆、线、文字、清屏。画面模块以后只调这套接口，换正式美术时只换这一个模块。带一个 `demo.html`。
4. **`modules/ui/`**：公共界面小件：按钮、文字、数字、面板、提示框，用 `render/` 画。带一个 `demo.html`。
5. **`app/`**：游戏的入口 `app/index.html`，加主循环和场景切换的空壳。打开是一个空的游戏画面，里面一个「试打」按钮，点了还没东西。
6. **`tools/`**：
   - 本地小服务；
   - 一条命令跑全部单测（`npm test`），不开浏览器；
   - 截图工具：能把任何一个 demo 页或游戏页截成图片，不用人去点。
7. **每个模块自带**：`index.js`（唯一的对外入口）、`README.md`（管什么、接口、读写哪些数据）、`test/`（不开窗口就能跑的单测）；画面模块再带一个 `demo.html`，用假数据单独跑起来看。
8. **三份文档**（`原型/README.md` 第 3 条）：`README.md`（怎么跑、怎么测、目录说明）、`进度.md`、`偏离.md`（哪里跟设计稿不一样、为什么，没有就写「没有」）。

**不要做的**
- 不做阶段 1 以后的东西：不写 `battle-rules`、`battle-view`、`content/`，也不写怎么打仗。
- 不先建一堆空目录：到了哪个阶段才建哪个（10.1）。
- 不改 `原型/<你的名字>/` 以外的任何文件，包括 `设计/`、`审核/`、根目录的 `进度.md` 和 `README.md`、别的原型目录。觉得设计有问题，写进你的 `偏离.md`，或者在交付时告诉用户。

**做完的标准**
- 双击 `启动.command`，浏览器里打开空的游戏画面，有「试打」按钮。
- `shared`、`render`、`ui` 的 demo 页都能从本地小服务打开。
- `npm test` 全部通过，不开浏览器。
- 截图工具能截下游戏页和每个 demo 页。
- 随便挑一个模块，它都不知道别的模块的存在：只 import `shared/`（画面模块再加 `render/`、`ui/`），只有 `app/` 把它们拼起来。

**提交**
- 本地 git 提交，提交信息开头写 `[<你的名字>]`，比如 `[neon] 阶段 0 搭架子`。**不推远端。**
- 只提交你自己目录里的文件，别用 `git add -A`：仓库里还有别人没提交的改动。

**交回来的时候说清楚**
- 做了什么、怎么跑、怎么测；
- 截了哪几张图、放在哪；
- 跟设计稿哪里不一样（`偏离.md` 里写了什么）；
- 设计稿里哪里没写清、你是怎么猜的。
