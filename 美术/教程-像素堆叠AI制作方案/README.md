# 像素堆叠（Sprite Stacking）AI 制作方案完全教程（v2）

本教程系统总结了一套经过实机验收的**程序化体素切片 + 像素堆叠（Sprite Stacking）**美术生产与渲染方案，适用于指导 AI 代理或开发者在**无 3D 软件 / 纯原生 Canvas 2D** 环境下，稳定、高速地制作 360° 俯视角像素堆叠资产与 60~120fps 游戏级交互场景。

> **使用界限说明**：本目录是一套**通用像素堆叠技术与美术工程方案**。当应用于本项目 **code00** 后续正式美术（`modules/render/stack/`）时，具体美术风格、配色、角色/怪造型及命名均需另按 `设计/设计.md` 与用户共创，不得直接套用演示案例的风格或旧样片命名。

## 1. 核心原理、格式约定与渲染管线

### 1.1 什么是像素堆叠
- 将 3D 物体沿垂直方向（Z 轴，从贴地 `z = 0` 到顶部 `z = H - 1`）切成 `H` 层水平切片，每层尺寸为 `W × D`。
- 渲染时从底层 `z = 0` 逐层向上叠画：每升高 1 层，屏幕 Y 坐标上移固定步进 `HS`（常用 `0.8` 格）；同时每层切片绕自身中心旋转镜头角度 `θ'`，并沿屏幕 Y 轴压扁 `TILT`（常用 `0.6`）。
- 只需一套切片，即可实现 **360° 任意角度平滑旋转**，兼顾像素艺术的锐利轮廓与真 2.5D 立体体积感。

### 1.2 坐标系、长条图集与元数据约定
| 约定项 | 规范 | 说明 |
|---|---|---|
| 单张长条 PNG 布局 | 宽 `W × H`、高 `D` | 第 `0` 层（贴地/最低点）在最左侧，往右依次为 `1, 2, …, H-1` 层；运行时直接按 `sx = z * W` 切片绘制，**不要**为每层各建一个 `<canvas>` |
| 坐标中心 | `X = x - W/2 + 0.5`，`Y = y - D/2 + 0.5` | 每层水平几何中心 = 物体落地中心（脚下 / 车底 / 树根正中） |
| 正面朝向 | **`+Y`（单层图片下方）** | 角色面部、怪正面、车辆车头统一朝向 `+Y` |
| 透明通道 | **严格 `alpha = 0` 或 `255`** | 严禁半透明、抗锯齿、边缘模糊 |
| 索引化调色板 | 全资产统一色表（≤ 48 色），体素网格存 `Uint8Array` 色表索引 | 杜绝色表外像素；支持游戏内按槽位精准换色、受击闪白、状态染色 |
| 悬空物体 | 第 `0` 层为物体最低有效层 | 通过清单中的 `lift` 字段整体抬升，不在切片底部浪费空层 |
| 游戏解耦元数据 | 清单记录 `footRadius`、`headZ`、`centerZ`、`activeLayers`、`glowLayers` | 跳过空层提速，同时为血条/盾条挂点、受击飘字和碰撞体提供标准锚点 |

### 1.3 标准投影与三种渲染模式选型
给定世界坐标 `(x, y, z)`、镜头中心 `(cx, cy)` 与镜头转角 `θ`：
```js
const rx = Math.cos(th) * (x - cx) - Math.sin(th) * (y - cy);
const ry = Math.sin(th) * (x - cx) + Math.cos(th) * (y - cy);
const screenX = CW / 2 + rx * sc;
const screenY = CH / 2 + OY * sc + ry * TILT * sc - z * step;
```
绘制切片时**必须关闭平滑（`ctx.imageSmoothingEnabled = false`）**。按实际场景从以下三种渲染模式中选择：

| 模式 | 原理 | 适用场景 | 性能与画质特征 |
|---|---|---|---|
| **1. 游戏生产模式：角度烘焙缓存（强烈推荐，见 `tihu/index.html`）** | 离屏按量化角度（如每 `2°` 或固定视角）把单个模型烘焙成 1 张紧凑 2D 精灵（内含双子步防漏缝、单体独立外轮廓与自遮挡发光层），配 LRU 缓存 | **真实游戏场景**（同屏数十个物体）与高清交互展示 | 每物体每帧仅 **`1` 次 `drawImage`**（`tihu` 实测从 300 次降至 **10 次**，稳跑 120fps）；前后物体轮廓完全分离不黏连 |
| **2. 高清实时逐层模式** | 直接在高清画布上跳过空层逐层放大 `SCALE` 倍绘制，每层抬高整数像素 `step = Math.max(1, Math.round(HS * SCALE))` | 单体调试、极速无缓存实时预览 | 任意角度锐利，但物体多时 DrawCall 线性爆炸 |
| **3. 复古低分模式** | 先在低分逻辑画布（`1 格 = 1 像素`）绘制，再整数倍最近邻放大 | 强复古点阵美学、锁 0°/90°/180°/270° 四正交视角 | 像素网格完全轴对齐，但非 90° 斜角配合 `0.8` 小数抬高会丢像素显糊 |

#### 必知坑：为什么高清模式下 `HS = 0.8` 容易出现「百叶窗层间黑缝」？
当 `HS (0.8) > TILT (0.6)` 时，单层切片被压扁后的屏幕垂直厚度约为 `0.6 × SCALE`，而每层向上抬升 `0.8 × SCALE`——相邻两层一旦水平错位（例如车架斜管、车轮辐条、倾斜枝干），就会在层间露出 `0.2 × SCALE` 像素的空缝。
- **工程解法（双子步压实 / Sub-step Extrusion）**：烘焙或逐层绘制时，若 `step > Math.floor(TILT * sc)`，先在 `yy + Math.round(step * 0.5)` 补绘一次同层切片，再在 `yy` 绘一次。在「角度烘焙缓存模式」下只在烘焙时多花一次算力，**运行时零额外开销**，彻底消除斜管断层与百叶窗黑缝。

### 1.4 2.5D 深度遮挡、发光层 Z 裁切与 1/4 降采样柔光
分离发光层（单独画到 `ec` 再 `screen` 叠光）极易产生**「X 光穿墙透视」**（被车篮、灯帽或前景物体遮挡的发光会透穿到最上层）和**全屏 `ctx.filter = blur` 掉帧**两大问题。标准解法：

1. **物体内部发光自遮挡**：在自下而上（`z = 0..H-1`）烘焙或绘制切片时，每升一层先用当前层**不透明实心切片**对发光层执行 `globalCompositeOperation = 'destination-out'`（抠除被上层实体盖住的下层发光），再以 `source-over` 绘制当前层发光像素。
2. **跨物体发光遮挡**：按画家算法从远到近（按 `ry` 升序）绘制每个物体时，先用前景物体的不透明剪影对场景发光缓冲 `ec` 执行 `destination-out`，再把前景物体自身的发光层叠进 `ec`。
3. **1/4 分辨率降采样柔光**：发光缓冲 `ec` 尺寸设为显示画布的 **`1/4 × 1/4`**（像素量仅为全屏的 `1/16`），在 `dctx` 合成时再做轻度 `blur` 并以 `screen` 放大叠加——Retina 高分屏下既柔和干净又能稳锁 60~120fps。
4. **DPR 逻辑一致性**：按 CSS 逻辑高度算基准缩放再乘 `Math.min(2, devicePixelRatio)`，确保 1x/2x 屏幕下滚轮缩放步幅、视野大小与外轮廓视觉粗细完全一致。
5. **大跨度/高遮挡物规则（游戏场景）**：长宽比悬殊的静止物体（如长围墙、长倒木）应拆分为近似正方形子块参与 Y-sort；主角走到高树冠/门廊背后时，按屏幕包围盒重叠加淡前景透明度或显露脚底轮廓。

## 2. 色彩、光影与接地感设计规范（7 条铁律）

像素堆叠切片不依赖实时 3D 光照，立体感完全由程序化着色与落地阴影决定。严格遵守以下 7 条铁律：

1. **光只分上下，严禁画左右方向光**
   - 物体会 360° 旋转，切片里一旦画了“左亮右暗”，转到背面光源立刻穿帮。
   - 所有明暗仅由 `z` 高度、朝上露边（`topEmpty`）、朝下底沿（`botEmpty`）与腔体遮蔽驱动。
2. **控色精简（≤ 48 色）+ 高对比 3 档色阶**
   - 单材质优先采用 **3 档高对比色阶（暗面 / 主色 / 露边亮色）**；过多相近灰阶在低分辨率下会揉糊轮廓。
3. **发光色必须与普通色物理隔离，并支持状态切换**
   - 非发光色键禁止与发光色键共用同一十六进制色值，防止误发光。
   - 若场景区分昼夜/开关状态，预烘焙一张将发光色替换为玻璃/熄灭色（如 `lampOff`）的替代表长条图集，白天自动熄灯、零运行时像素扫描。
4. **精细体素着色：露边提亮 + 上方 3×3 腔体 AO + 白名单部件暗缝 + 局部高度**
   - **露边提亮**：`z + 1` 为空的像素（`topEmpty`）提亮一档，交代水平切面轮廓；球顶类形态避免每层涂最亮白造成同心条纹。
   - **白名单部件接缝（Crease AO）**：给体素记录 `partId`，不同部件相接处压暗一档切出清晰缝隙（如上喙与喉囊、翅膀与白羽躯干），但须配置**免暗缝白名单**（如 `eye:neckHead`、`lampLens:lampBody`、`bar:grip`、`wheelRim:wheelSpoke`），防止细小部件或眼眶周围整体发黑。
   - **上方 3×3 腔体 AO**：检查 `z + 1` 层周围 8 邻域的实心遮蔽数，自然压暗同部件内的真实凹槽（腋下、篮内底、坐垫下方）。
   - **部件局部归一化高度**：统计每个 `partId` 的 `[minZ, maxZ]`，让长柱体（如路灯木柱）或悬空部件自带底部压暗过渡，并辅以金属箍环/台阶结构打破单调。
5. **厚度 ≥ 2 格 + `despeckle()` 孤立像素清理**
   - 树枝、草叶、车架管、辐条、四肢、尾巴等细结构半径应 `≥ 1.05~1.25`（截面 ≥ 2×2 格），避免斜角旋转碎成闪烁噪点。
   - 建模完成后统一执行 `despeckle(protectedParts)` 清理 3D 孤立单像素（白名单保护眼睛、灯芯等刻意 1px 细节）。
6. **相邻层平滑过渡，交界一律 `smin` 融合**
   - 相邻两层水平轮廓错开尽量 ≤ 1 格；躯干接脖子、树干接树冠等有机衔接严禁直角硬拼，一律使用平滑并集 `smin(a, b, k)`。
7. **双层接地阴影与贴地光斑（消除「贴纸漂浮感」）**
   - **轮廓投射影（Cast Shadow）**：离线生成模型全高度向地面投影的水平足迹剪影（`footShadow`），按偏移量淡化贴在地面上；
   - **深色接触影（Contact Shadow）**：在轮胎触地点、角色脚下、柱基处紧贴落脚点叠加更实的深色椭圆/圆接触影；
   - **地面氛围光斑**：夜色/黄昏下，车灯光锥与路灯暖光斑画在地面层世界矩阵中，并严格使用 `clip()` 裁切在有效地面边界内，杜绝光束溢出背景。

## 3. 高性能体素建模工程方案（纯 JS 零外部依赖）

AI 不擅长逐像素手绘位图，但非常擅长**数学建模（SDF）+ 程序化着色**。为了兼顾代码可读性与极速构建，遵循以下工程准则：

### 3.1 第 0 步：先写「部件空间坐标预算表（Part Bounding Box Budget）」
**AI 写 SDF 最高发的事故不是语法错，而是空间坐标算错把配件埋进另一个部件里**（例如车灯中心 `Y = 12.8` 误掉进车篮 `Y ∈ [11.2, 16.8]` 内部）。写代码前必须先列出所有部件的 `X / Y / Z` 区间、谁在谁的外侧/上方，确认零误遮挡再编码。

### 3.2 核心性能优化：`Uint8Array` 索引网格 + 部件级 AABB 局部扫描
一个典型堆叠模型（如 `36×60×46 = 99,360` 体素）里，**实心体素通常只占 4%~10%，超过 90% 都是空气**。
- **反面教材**：用 JS 字符串数组存色键，并在三层全盒循环里对每一个空气体素运行几十次 SDF 计算——8 帧角色构建耗时高达 **`875ms`**。
- **标准做法（见 `tihu/index.html`）**：
  1. `grid = new Uint8Array(w * d * h)`（`0` 为空、`1..48` 为色表 ID、`128 + matId` 为待着色语义材质标记）与 `parts = new Uint8Array(w * d * h)`；
  2. 提供 `fillAABB(X0, X1, Y0, Y1, Z0, Z1, fn)`、`paintCapsule(...)`、`paintEllipsoid(...)`，每个部件**只遍历自身最小包围盒内的体素**；
  3. 实测 8 帧鹈鹕构建时间直接从 **`875ms` 压到 `~60ms`（提速 14 倍）**！

### 3.3 必备数学与程序化原语
- **平滑并集 `smin(a, b, k)`**：`k = 1.0 ~ 2.4` 用于躯干/颈/头、树干/树冠柔和过渡。
- **3D 胶囊线段 `distSeg3Sq(p, a, b)` + 变半径折线 `polyDist`**：构建车架、四肢、围巾、翅膀、枝干；用平方距离判定省去内层 `Math.sqrt`。
- **周期性无缝噪声 `periodicNoise2(x, y, periodX, periodY, cell, seed)`**：用于无缝地面与无限滚动场景；多张地面变体需彼此混拼时，让四边外圈 `10px` 通过 `smoothstep` 收敛到共享边界场。
- **后置精确细节**：眼睛、符文、钉孔等关键细节在统一着色后单独落点——固定从外侧沿同列向内扫描找到最外层实体像素落点，确保垂直对齐不断裂且不被上方结构遮挡。

### 3.4 零依赖 PNG 导出与游戏换色
- **Node 离线产线**：使用内置 `zlib.deflateSync` + ~30 行 CRC32/Chunk 拼接直接写出标准 8-bit RGBA 长条 PNG，无需任何 `npm install`。
- **浏览器交互工具**：直接通过长条 Canvas `toDataURL('image/png')` 一键导出规范 PNG（见 `tihu/index.html` 的「导出长条 PNG」按钮）。
- **运行时精准换色**：由于体素网格本身基于调色板索引（且发光组隔离），离线可同步输出索引表或分槽位调色板 JSON，游戏内切换敌怪配色、受击全白闪烁、破盾高亮时只需替换调色板查表重生成长条，零误伤且极快。

## 4. 动画与物理同步设计要点

1. **精确 2-Bone 平面解析 IK（替代会拉伸变形的 `lerp` 近似）**
   - 涉及双腿踩踏、行走摆臂或机械连杆时，不要用简单线性插值凑膝盖/肘部坐标（会导致骨长忽长忽短）。用 6 行余弦定理 `solveIK2D(hy, hz, ty, tz, L1, L2, bendDir)` 严格保持大腿 `L1` 与小腿 `L2` 恒长，关节弯曲方向自然且全程零误差：
     ```js
     function solveIK2D(hy, hz, ty, tz, L1, L2, bendDir = 1) {
       const dy = ty - hy, dz = tz - hz;
       const d = clamp(Math.hypot(dy, dz) || 0.001, Math.abs(L1 - L2) + 0.05, L1 + L2 - 0.05);
       const base = Math.atan2(dz, dy);
       const cosA = clamp((L1 * L1 + d * d - L2 * L2) / (2 * L1 * d), -1, 1);
       const ang = base + bendDir * Math.acos(cosA);
       return [hy + Math.cos(ang) * L1, hz + Math.sin(ang) * L1];
     }
     ```
2. **轮速与地速物理纯滚动同步（`v = 2πR · freq`）**
   - 载具/移动演示必须将地面纹理滚动速度、路旁景物移动速度与车轮角速度严格绑定：`GROUND_SPEED = revPerSec * 2 * Math.PI * WHEEL_RADIUS`，彻底杜绝“轮子空转”或“路灯在静止地面上滑冰”。
   - 圆形底座演示中，预制纵向严格周期无缝的长条地面（例如周期 `32px`、木板周期 `8px`），每帧按 `scroll % period` 采样后用圆形蒙版 `destination-in` 裁切再叠固定边环，耗时 < 0.05ms。
3. **多状态与局部运动分离**
   - 复杂生物拆成外层姿态状态与内层循环相位；扇翅偏移在翼根 `t = 0` 处恒为 `0`（翼根稳固、翅尖大幅摆动）；强包覆形态直接切换专用壳体模型，不靠硬旋转平面穿模。
4. **镜头最短角复位**
   - 支持自由 360° 旋转的查看器，点击重置视角前须将当前角 `th` 规整到 `[thTarget - π, thTarget + π]` 最短角区间，避免转过多圈后复位时疯狂倒转。

## 5. 零依赖「量化校验 → 渲染看图 → 迭代打磨」闭环

AI **绝不能盲写代码直接交货**。每次生成或大改资产必须跑通以下三步闭环：

### 5.1 第一道关：自动化量化与空间遮挡校验（Node 脚本 1 秒跑完）
在看图前先跑自动化断言，直接拦住 80% 的低级错误：
- **合规检查**：色表数 ≤ 48、零重复十六进制色值（发光色完全隔离）、零未着色材质残留、零半透明像素、零 3D 孤立碎点、除贴地 `z = 0` 外不触碰包围盒边界。
- **关键锚点可见性射线断言（最有效！）**：从眼睛、车灯透镜、武器尖端等关键部件出发，沿正面 `+Y` 和默认斜前俯视射线扫描，**断言被其他部件遮挡的体素数 = 0**（这一条 6 行代码即可在 0.1 秒内抓出“车灯埋进车篮”或“刘海压住眼睛”）。
- **性能与动画断言**：记录全帧建模耗时（单模型 8 帧建议 `< 100ms`）、有效非空层比例、以及 IK 骨长守恒最大误差（应 `< 0.01`）。

### 5.2 第二道关：双轨零依赖看图自检（不再硬绑 `@napi-rs/canvas`）
- **轨道 A（优先，所见即所得）**：起本地静态服务，用无头浏览器 / Electron / Playwright 实机打开页面，截取 **正（0°）/ 斜 45° / 侧（90°）/ 背（180°）+ 各氛围模式 + 1:1 实际尺寸** 截图，同时核查真实 Console、帧率、DrawCalls、`ctx.filter` 柔光与 DPR 表现。
- **轨道 B（纯 Node 无网离线兜底）**：若环境无浏览器且无法装外部原生包，直接用 ~60 行纯 JS 最近邻仿射光栅器将 `VoxelModel` 切片按 `TILT = 0.6`、`HS = 0.8` 投影写入 RGBA `Uint8Array`，再用内置 `zlib` 导出 PNG 预览图——实现 **100% 全链路零外部依赖**。

### 5.3 典型实测缺陷与修复案例库
| 实测缺陷 | 根因 | 修复方案 |
|---|---|---|
| 前车灯完全看不见，车篮里泛白团 | 车灯坐标 `Y=12.8` 落在车篮内部，且独立发光层无 Z 遮挡透穿木壁 | 建「空间坐标预算表」将车灯支架外移至车篮前壁 `Y=16.0` 之外；发光层加 `destination-out` 遮挡裁切 |
| 骑行时路灯滑行、木栈道纹丝不动 | 仅滚动了景物 `propY`，未同步滚动周期地面纹理 | 预制 32px 无缝周期地面长条按 `v = 2πR · freq` 同步偏移裁剪 |
| 8 帧角色初始化卡顿近 1 秒（875ms） | 95.7% 空气体素全量跑 SDF + 字符串数组 + 720 个独立 `<canvas>` | 改为 `Uint8Array` + 部件级 `fillAABB` 局部遍历 + 单张长条图集（降至 **~60ms**） |
| 高分斜角下斜管/辐条现层间黑缝 | `HS (0.8) > TILT (0.6)` 导致错位层露出 `0.2 × SCALE` 缝隙 | 烘焙时加半步压实绘制 `yy + Math.round(step / 2)` 彻底补实 |
| 前后物体重叠时轮廓黏成一团 | 全场景实体合并到 `mc` 后统一描边 | 改为游戏级「角度烘焙缓存」，每个物体离屏自带单体独立描边 |
| 晴朗白天路灯依然发亮光 | 仅调低 `glowAlpha`，未替换白天熄灯切片颜色 | 预生成 `stripDay` 熄灯替代表并置 `emitGlow = false` |
| 俯视时角色眼睛被额头/上喙遮挡 | `0.6` 俯视倾角下上方突出结构压住眼层 | 眼睛置于侧前最外层表面且做俯视射线遮挡断言，保证垂直同列对齐 |
| 球形头顶出现一圈圈白色条纹 | 每层 `topEmpty` 均涂最亮高光 | 顶面内部改过渡色，仅最高 1~2 层外轮廓点亮边 |

### 6.2 对接 code00 渲染模块的标准资产清单（供阶段 5 正式美术使用）
为满足 `设计/设计.md` 第 10 节「先做色块原型 `modules/render/blocks/`，后期零改玩法无缝切换 `modules/render/stack/`」的要求，未来每个正式像素堆叠模型应随长条 PNG 附带统一 JSON 元数据：
```json
{
  "id": "unit_example",
  "strip": "unit_example_36x60x46.png",
  "w": 36,
  "d": 60,
  "h": 46,
  "frames": 8,
  "lift": 0,
  "footRadius": 15,
  "headZ": 44,
  "centerZ": 24,
  "glowKeys": ["emissiveCore", "emissiveRim"],
  "tintSlots": {
    "primary": ["coatDark", "coatMid", "coatHi"]
  }
}
```
- `footRadius`：探索地图碰撞与接地接触影半径；
- `headZ`：战斗与地图中头顶血条、韧性盾条、倒计时图标的标准屏幕挂点高度；
- `centerZ`：伤害飘字、受击特效与死亡消散粒子的标准锚点高度；
- `tintSlots`：同骨架不同变体配色及受击闪白/破盾高亮的查表槽位。
