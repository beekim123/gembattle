# 开发计划的做法（调查，2026-11-24，claude）

**为什么有这份**：用户问「这种游戏，各个厂商和个人开发者是怎么规划、怎么一级级安排开发和设计的？我现在的流程对不对？」。这里记查到的做法、跟我们对照的结果，还有几条建议。**第四节的建议用户还没点头，别当成定了。**

`做原型的方法.md` 讲的是「原型这一步」怎么做；这一份讲的是从头到上线整条线怎么排。

## 一、业内一般分几段

各家叫法不一样，顺序差不多：

| 段 | 要回答的问题 | 过了这段要有什么 |
|---|---|---|
| 1. 想法 | 想做个什么 | 能一两句话说清核心体验 |
| 2. 原型 | 值不值得做 | 找到至少一个「好玩的点」；没把握的地方列出来，每处有办法去试 |
| 3. 垂直切片 | 能不能做好 | 一小段做到接近上线的样子（玩法、美术、声音都有），让人信服；游戏多大定下来；排期按试过的做法估 |
| 4. Alpha | 功能齐没齐 | 所有功能都在，从头能玩到尾，可以先用临时美术 |
| 5. Beta | 内容齐没齐 | 内容全进去了，只修 bug、小调，不再大改 |
| 6. 上线、更新 | | |

1~3 叫「前期」，4 以后叫「正式做」。前期允许乱、允许推倒，正式做要稳。

- **Mark Cerny 的 Method**（做过《古惑狼》《小小大星球》《PS5》）：
  - 前期和正式做「像白天和黑夜一样不同」，前期本来就该乱；
  - 他说游戏开发里八成的错是前期做了或没做什么造成的；
  - 前期交两样东西：一个「能拿去卖的第一版」（两三关，做到上线的品质），和一份讲游戏多大的「宏观设计」；
  - 前期一般做 2~5 个原型；
  - 不写四百页的设计文档，只写五页的简短说明；
  - 做不出这个第一版，或者做出来发现不比同类已上线的游戏强，就砍掉，因为「项目不会在正式做的时候奇迹般变好」。
- **Supercell**：小组一直在做原型，大多数在原型阶段就砍了。有一次讲到最近 10 个游戏：7 个死在原型，2 个死在小范围上线，只有 1 个（皇室战争）全球上线。砍不砍由小组自己定。
- **国内厂商**：一般是 Demo → 立项评审 → 正式开发（Alpha / Beta）→ 封测 → 公测。
  - Demo 常常只做核心玩法，但做到心目中上线的标准，好让老板有信心立项（就是垂直切片）；
  - 有的先拿 Demo 去街上找路人测「尖叫度」，数据好才立项；
  - 调数值放在封测，那时才有真玩家的留存这些数。

## 二、卡牌肉鸽和个人开发者是怎么走的

| 游戏 | 怎么开头 | 谁来试 | 后面怎么走 |
|---|---|---|---|
| 杀戮尖塔（两个人） | 2015 年开做，先做了个原型试，**好玩，就把原型扔了重写** | 头两年只给一小撮人试，找的是 Netrunner（一种卡牌桌游）的高手，说话直、不客气 | 做了三年多：两年内部试，一年在 Steam 抢先体验，抢先体验时才收全部玩家的数据调平衡 |
| 小丑牌（一个人） | 休假三周做了个「怪原型」，**连小丑都没有**，只有筹码 × 倍率；做完一周就发给朋友 | 朋友。他发现这个不一样，是因为一个朋友说已经玩了二三十、三四十个小时 | 后面几个月才加小丑、商店、Boss；一年多后辞职全职；再往后才加教程、手柄、音效；先 Steam 公开测试，再出试玩版，再上线 |
| 邪恶冥刻（一个人） | 48 小时游戏比赛做的小游戏，规则几乎没想就定了 | 放到 itch.io 给陌生人玩，反响好 | 才扩成完整的游戏 |
| 怪物火车（小团队） | 公司内部游戏比赛，**4 个小组同时做好几个原型**；最初的版本是城堡、即时制，跟最后很不一样 | 做了个低成本原型拿去找发行商，被拒了很多次 | 原型做成更好看的「第一版」拿去谈；Alpha、Beta 里每个人按 F8 就能提意见、附截图和存档；排期只问「现在最要紧的是什么」，听着好但不要紧的就推后或砍掉 |
| 冰霜原野（小团队） | 一个人先做的**纸上原型** | 团队 | 原型长到一定程度（半年）才开始正式开发 |
| 一个人做的小卡牌游戏 | 一个月：第 1 周想点子和牌，第 2~3 周做循环，第 4 周打磨 | | |

**Derek Yu**（《洞窟探险》作者）讲怎么把游戏做完：
- 整个游戏从头到尾能玩之前，别在哪一块上花太久；
- 打磨留到最后；
- 给游戏自己设限，才做得完；
- 拿给别人看反应平平，往往该早点做完、做下一个，而不是一直修。

**试玩**：
- 设计的人和一直跟着看的人都知道「应该怎么玩」，看不出问题；第一次玩的陌生人才看得出。
- 一般顺序：自己先玩 → 朋友 → 再给陌生人。找爱玩这类游戏的人，几乎什么都不解释，看他们怎么玩。
- 太早**公开**粗的版本会留下坏印象；私下给几个人试没这个问题。

## 三、对照我们

**跟业内一样、走对了的**：
1. **先做核心、再一层层加，加了不好玩就删**（`做原型的方法.md`、设计稿 10.4、10.7）。小丑牌第一版没小丑，杀戮尖塔先做原型试，Cerny 的前期本来就是「试，不行就扔」。
2. **一次只改一处**。
3. **现在不调平衡**。杀戮尖塔是抢先体验时拿全部玩家的数据调的，国内是封测时调的，都是在好玩之后、内容基本齐了以后。
4. **原型的代码能扔**。杀戮尖塔的原型做完就扔了。我们模块是拆开的，外圈关着不加载，也是这个意思。
5. **找别家来审**。相当于团队里互相挑刺。

**走偏了、或者缺的**：
1. **先写了一份很大的设计稿，后面才做核心。** 设计稿现在 1182 行，前后审了三轮，大部分写的是外圈（工会、任务、装备、队友、加成）。可核心直到第 7 版才单独拿出来让用户打。Cerny 只写五页，业内的设计文档是「跟着做慢慢长」的。这一段已经纠正过来了（第 7 版回到核心）。剩下的问题是：设计稿里外圈那些章节还写得像「定了」，以后一层层加的时候很可能要改。
2. **只有用户一个人在打。** 用户既是设计的人，又是唯一玩的人；假玩家只能量数，量不出好不好玩。杀戮尖塔、小丑牌、邪恶冥刻都是靠**别人**的反应知道「这个行」的。小丑牌最关键的信号，就是朋友自己玩了几十个小时。
3. **每层没有时限，也没写清楚什么时候砍。** 核心有过关标准（`做原型的方法.md` 第三节），可没有「打几天还不行就换」。业内原型一般按周算，有的四周找不到好玩就认为核心不对；Supercell、Cerny 都事先说好什么情况砍掉。
4. **还没有「一两句话说清这个游戏」。** 第一段要求能一两句话说清核心体验。每加一层，拿这句话一比，就知道这层是帮着它还是跑偏了。现在判断一层留不留，只有「更好玩没有」，标准有点虚。
5. **美术跑在玩法前面一点。** `美术/` 那条线已经做了 45 只怪的模型，可怪在战斗里干什么还没跟用户一起设计（设计稿第 11 节「以后」）。业内是：前期定美术风格、做一小段切片看看效果，**大量出美术等到正式做**。风格和做法先试是对的，量产先别太快。（`美术/` 是用户和 neon 的，这里只是提醒，不改。）

## 四、建议（等用户点头）

**整条线照业内排成这样**（我们现在在第 1 段中间）：

| 段 | 做什么 | 过关标准 | 对应业内 |
|---|---|---|---|
| 1. 核心和几层（现在） | 核心试玩 → 一层层加：打完一仗牌组怎么变 → 功能牌、加成 → 队友 → 外圈。每层画面、设计、代码三条验收（10.7） | 每层：用户打了说更好玩，不然删 | 原型 |
| 2. 给外人打 | 核心 + 前一两层做完，私下发给三五个爱玩卡牌肉鸽的人，几乎不解释，看他们打多久、卡在哪 | 有人不用催自己再来 | 原型的试玩 |
| 3. 一小段做像样 | 一趟里的一小段，换上用户的像素堆叠怪、加声音，从头到尾像上线的样子 | 用户和外人看了觉得「这就是这个游戏」；美术一只怪做进战斗要多久心里有数 | 垂直切片 |
| 4. 功能齐 | 大厅、工会、任务、装备都接上，从头能玩到尾 | 所有功能都在 | Alpha |
| 5. 内容齐、调平衡 | 怪、牌、加成做够数，假玩家 + 真人数据一起调 | 不再加新东西 | Beta |
| 6. 试玩版、上线 | | | |

**三条具体的**：
- **A. 尽早给外人打**：做完第一层（打完一仗牌组怎么变）以后，私下给三五个人打。倾向：做。
- **B. 每层定个时限**：比如一层做出来，用户打一两天还说不出好在哪，就换候选或删掉，不一直修。倾向：做，时长用户定。
- **C. 写一两句话的「这个游戏是什么」**：放在设计稿最前面，用户定。每加一层拿它比。倾向：做，先出两三个候选给用户挑。

**不建议做的**：
- 现在就砍设计稿里外圈那些章节。它们留着当「以后可能这样」的参考就好，等加到那一层再跟用户重新对。
- 现在就排日期。一个人加模型做，按「段」走比按日期走实在。
