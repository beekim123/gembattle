### 二、现在的设计是什么样

- **21 个生境**：原有 18 个（`scenes/habitats.js` 里有地台），每个加了一条「这里才有的规矩」和「最底下靠什么吃」；新增 3 个：巨兽遗骸 `carcass`、盐壳湖 `saltlake`、热泉梯田 `hotspring`。**新增的 3 个还没有地台**，数据里写了配色（`pal / sky / fx`，跟 habitats.js 同一格式）和「地面怎么画」（`ground`）。

- **73 只生物**，`status` 的意思：
  - `made`：已有模型，`impl` 是工坊里的脚本 id，共 29 只；
  - `existing`：图鉴里有、还没做模型，16 只；
  - `decided`：用户定了，只有「沙6 假水洼」；

- 每只新设计都有：长相、一天怎么过、一眼认得出的动作、动作照什么来、吃什么、跟谁一起过、给做模型的人看的做法要点、同类变体。

### 三、任务一：审核生态设计

结果写进 `审核/neon/<当天日期>-生态设计第1版.md`。规矩照 `审核/README.md`：只往自己目录写；按「必须改 / 建议改 / 以后再说」分；每条写清楚是哪一只或哪个生境（用编号）、为什么、建议改成什么。

要查的：

1. **生态说不说得通**：每个生境的食物网有没有断头（谁都不吃它、它什么都不吃，又说不出理由）；捕食关系的体型、生境对不对得上；生境之间的连接合不合理。
2. **够不够异世界、有没有落进俗套**：规矩是「动作照地球生物的力学，长相、材料、吃法、关系放开编」。要避开「地球动物直接放大」和奇幻老一套（元素精灵、发条机器人、三头犬、宝箱怪、林边村子、旧书 / 木偶 / 眼珠子变的怪）。
3. **能不能做**：每只新设计照它的模板，在像素堆叠 + 28MB 贴图上限下做不做得出来；`note` 里的做法有没有写错；哪些要先等 core 加痕迹层、画线、跨个体挂点。
4. **用词**：不取正式名字，只写长相和干什么；不用 灯 烬 影 夜 魂 噬 幽 渊 星 光 这些字，也不用「守×者」「×之×」这种格式。界面上的文字也算。
5. **claude 自己知道的薄弱处**：
   - 热泉梯田、盐壳湖各只有 2 只，食物网太薄；
   - 巨兽遗骸缺伏击和寄生；
   - 水4 吃什么是提案，但没标 `nicheProposal`；
   - 地图坐标是随手排的。

怎么处理：

- **不改方向的直接改** `生态设计数据.js`：引用错、前后矛盾、模板归错、某只吃的东西那个生境里根本没有、做法写错、禁用字。审核文件里每条记「已改」。
- **要换设计的**（换一只生物、改生境规矩、增删生境、补薄弱的食物网）：怪、技能、世界观照规矩要跟用户一起设计。每处出 2~3 个真不一样的候选，附上你的倾向，集中放在审核文件「要用户拍板」一节，让用户一次看完、可以一句「按倾向定」。没拍板之前不改数据。

### 四、任务二：把生态总览页改成「一眼看得懂」

用户的原话大意：「现在是纯文字版，字有点多。要可视化：大致画一张简单的平面地图，我点哪块，就去看那块的生态图（工坊那种有生物在里面的）；每只生物有单独的百科介绍。让我用肉眼就能很直观地看出现在设计的是什么。给 AI 看的对应关系单独用 md 文档做；HTML 是给人看的，要直观。」

**页面要有这三层**（具体长什么样由你设计，**先做出地图 + 一个生境 + 一只百科，截图给用户看一眼，用户点头再铺开全部**）：

1. **世界地图（首页）**
   - 一张简单的平面地图：21 个生境是 21 块区域，用各自的配色或像素色块画；摆放要合地理：水从山上流到海，沙漠在一边，天上、地下也要有个直观的放法（比如天上画成飘在上方的云块，地下画成地图下面的一条剖面）。
   - 生境之间的连接画成看得见的东西：河是蓝色的线，迁徙是虚线或小脚印，一生、尸体、热这几种各有一眼能分开的画法。不靠文字说明。
   - 鼠标放到一块区域上：显示名字和一排住在这里的生物小头像；点进去就是这块的生态图。新增的 3 个生境要一眼看出是新的。
   - 字越少越好。

2. **生境生态图（点进一块区域）**
   - 用工坊的渲染器把这个生境的地台和住在这里的生物放上台跑起来，就像工坊预览台那样。
   - 已有模型的用真模型；还没有模型的用**统一的占位**（建议：按体型大小、按生态位配色的简单色块体素，头顶一个编号小牌）。以后模型做好了，要能自动换上。
   - 「谁吃谁」要看得见：比如在台上生物之间画可开关的箭头，或者旁边放一列用生物小头像排的食物链。
   - 顶上一行写这里才有的规矩（一句话），加上最底下吃的东西（用图标）。
   - 点台上的生物，或者点头像，进它的百科。

3. **生物百科（每只一页）**
   - 大图：有模型的放真模型，能转、能看待机和巡游；没模型的放占位，标「待做」。
   - 关键信息用图标或标签，不用整段字：生境、模板、生态位、体型、状态。
   - 关系用小头像：吃什么、被谁吃、跟谁一起过、挂在谁身上。
   - 「一眼认得出的动作」一句话放显眼处；长相、一天怎么过写成短段落；「给做模型的人看的」做法要点默认折叠。
   - 能翻上一只、下一只，能回生境、回地图。

**另外**：

- 四种状态（已有模型 / 图鉴里有 / 定了 / 提案）要一眼分得清，比如头像上的角标颜色。
- 能用浏览器回退：`#map`、`#hab/<生境 id>`、`#c/<编号>`。
- 现在页面上的大表格（生态位 × 生境、模板表、连接清单）挪去 md，HTML 里不放，或者只留一个不显眼的入口。

**给 AI 看的 md**：

- 新建 `文档/生态设计-对应关系.md`，内容包括：
  - 生境 → 住着谁；
  - 每只的编号、名字、生境、模板、生态位、吃、被吃、一起过、宿主、状态、模型脚本 id；
  - 模板 → 标杆和同类；
  - 生境之间的连接；
  - 生态位 × 生境表。
- **用脚本从数据生成，别手写**，比如 `node tools/eco-md.js`，免得跟数据对不上。
- 脚本顺手做一遍检查：编号、吃食、生境、模板都存在，没有重复，没有禁用字。claude 用过一段临时检查，思路一样，可以写进这个脚本。

### 五、工程上的规矩

- **数据只有一份**：`文档/生态设计数据.js`。地图需要的区域形状、头像颜色这类，可以加进数据，或者另开一份 `文档/生态地图布局.js`。
- **工坊要解耦**：生态页复用 `core/`、`scenes/habitats.js`、`creatures/` 和 `StackRenderer`，不改它们原来的行为。
  - 要改 core 的（比如加占位体素、给新增的 3 个生境加地台，加进 `scenes/habitats.js`），改完照 README 跑一轮压测，跟 README 里的数字对一下。
  - 工坊首页 `index.html` 不能被改坏，顶栏的「生态总览」入口保留。
- **性能**：一次只跑一个生境的舞台，离开就停；全页只用一个渲染器；贴图守 28MB 上限；别另开整屏大小的离屏画布。
- **清晰**：放大倍数取整数、常态不拉伸、关掉平滑（工坊的规矩）。
- 界面中文，最小字号 12。直接双击 `ecology.html` 也要能打开（跟工坊一样）。
- `美术/` 是用户自己的，**不提交**。每做完一步，在仓库根 `进度.md` 的「记录」加一行，写清楚改了哪些文件；只提交 `进度.md` 和 `审核/neon/` 下面你的文件，提交说明开头写 `[neon]`，不推远端。
- 另外有会话在改 `原型/neon/`（游戏原型），别碰那边的文件。
- 要停之前，把 `进度.md`「现在」里美术那一段写好：做到哪、下一步。
