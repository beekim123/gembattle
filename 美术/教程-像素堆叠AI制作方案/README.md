# 像素堆叠（Sprite Stacking）AI 制作方案完全教程（v3：骨骼化 + 整体轮廓 + 旋转满帧）

本教程系统总结了一套经过实机验收的**模块化程序化体素切片 + 120fps 连续运动学骨骼 + 局部整体外轮廓 + 像素堆叠（Sprite Stacking）**美术生产与渲染方案，适用于指导 AI 代理或开发者在**无 3D 软件 / 纯原生 Canvas 2D** 环境下，稳定、高速地制作 360° 俯视角像素堆叠生物、道具与 60~120fps 游戏级交互场景。

> **使用界限说明**：本目录是一套**通用像素堆叠技术与美术工程方案**。当应用于本项目 **code00** 后续正式美术（`modules/render/stack/`）时，具体美术风格、配色、角色/怪造型及命名均需另按 `设计/设计.md` 与用户共创，不得直接套用演示案例的风格或旧样片命名。

## 1. 核心原理、格式约定与渲染管线

### 1.1 什么是像素堆叠
- 将 3D 物体沿垂直方向（Z 轴，从贴地 `z = 0` 到顶部 `z = H - 1`）切成 `H` 层水平切片，每层尺寸为 `W × D`。
- 渲染时从底层 `z = 0` 逐层向上叠画：每升高 1 层，屏幕 Y 坐标上移固定步进 `HS`（常用 `0.8` 格）；同时每层切片绕自身中心旋转镜头角度 `θ'`，并沿屏幕 Y 轴压扁 `TILT`（常用 `0.6`）。
- 只需一套切片，即可实现 **360° 任意角度平滑旋转**，兼顾像素艺术的锐利轮廓与真 2.5D 立体体积感。

### 1.2 坐标系、长条图集与元数据约定
| 约定项 | 规范 | 说明 |
|---|---|---|
| 单张长条 PNG 布局 | 宽 `W × H`、高 `D` | 第 `0` 层（贴地/最低点）在最左侧，往右依次为 `1, 2, …, H-1` 层；运行时直接按 `sx = z * W` 切片绘制，**不要**为每层各建一个 `<canvas>` |
| 坐标中心 | `X = x - W/2 + 0.5`，`Y = y - D/2 + 0.5` | 每层水平几何中心 = 部件或物体落地中心 |
| 正面朝向 | **`+Y`（单层图片下方）** | 角色面部、怪正面、车辆车头统一朝向 `+Y` |
| 透明通道 | **严格 `alpha = 0` 或 `255`** | 切片本身严禁半透明、抗锯齿、边缘模糊（水下浸没柔隐在运行时合成阶段处理） |
| 索引化调色板 | 全资产统一色表（≤ 48 色），体素网格存 `Uint8Array` 色表索引 | 杜绝色表外像素；支持游戏内按槽位零重建模换色、受击闪白、状态染色 |
| 悬空部件 | 第 `0` 层为部件最低有效层 | 通过 `lift` 字段整体抬升，不在切片底部浪费空层 |
| 游戏解耦元数据 | 清单记录 `footRadius`、`headZ`、`centerZ`、`activeLayers`、`glowLayers` | 跳过空层提速，同时为血条/盾条挂点、受击飘字和碰撞体提供标准锚点 |

### 1.3 标准投影与三种渲染模式选型
给定世界坐标 `(x, y, z)`、镜头中心 `(cx, cy)` 与镜头转角 `θ`：
```js
const rx = Math.cos(th) * (x - cx) - Math.sin(th) * (y - cy);
const ry = Math.sin(th) * (x - cx) + Math.cos(th) * (y - cy);
const screenX = CW / 2 + rx * sc;
const screenY = CH / 2 + OY * sc + ry * TILT * sc - z * step;
```
绘制切片时**必须关闭平滑（`ctx.imageSmoothingEnabled = false`）**。按实际场景从以下三种渲染模式中选择：

| 模式 | 原理 | 适用场景 | 性能与画质特征 |
|---|---|---|---|
| **1. 游戏生产模式：定倍角度烘焙缓存（强烈推荐，见 `examples/`、`snake/`、`siren/`）** | 以**与屏幕缩放解耦的黄金倍率 `BAKE_SCALE = 2.5`**（精确满足 `0.8 × 2.5 = 2.0` 整数步进 + `1px` 半步压实）按 `3°` 量化离屏烘焙紧凑 2D 精灵，配 Canvas 对象池与对称共享（如 `symDeg = 90`）；多部件生物在局部 `actorBuf` 中拼合后做 1 次整体外轮廓 | **真实游戏场景**与 360° 自由旋转骨骼生物展示 | 单体物体每帧 `1` 次 `drawImage`，21 部件骨骼生物约 `37` 次绘制；实测连续拖拽/自动旋转与全技能爆发全程稳跑 **`108~120fps`（单帧 `0.2~0.5ms`）**，滚轮缩放 100% 不清空缓存 |
| **2. 高清实时逐层模式** | 直接在高清画布上跳过空层逐层放大 `SCALE` 倍绘制，每层抬高整数像素 `step = Math.max(1, Math.round(HS * SCALE))` | 单体调试、极速无缓存实时预览 | 任意角度锐利，但物体多时 DrawCall 线性增长 |
| **3. 复古低分模式** | 先在低分逻辑画布（`1 格 = 1 像素`）绘制，再整数倍最近邻放大 | 强复古点阵美学、锁 0°/90°/180°/270° 四正交视角 | 像素网格完全轴对齐，但非 90° 斜角配合 `0.8` 小数抬高会丢像素显糊 |

#### 必知坑 1：为什么高清模式下 `HS = 0.8` 容易出现「百叶窗层间黑缝」？
当 `HS (0.8) > TILT (0.6)` 时，单层切片被压扁后的屏幕垂直厚度约为 `0.6 × SCALE`，而每层向上抬升 `0.8 × SCALE`——相邻两层一旦水平错位（例如斜管、辐条、倾斜躯干/翅膀），就会在层间露出 `0.2 × SCALE` 像素的空缝。
- **工程解法（双子步压实 / Sub-step Extrusion）**：在 `BAKE_SCALE = 2.5` 下，每层精确步进 `2px`，先在 `yy + 1`（半步）补绘一次同层切片，再在 `yy` 绘一次。在角度烘焙缓存模式下只在烘焙时多画一次，**运行时零额外开销**，彻底消除斜管断层与百叶窗黑缝。

#### 必知坑 2：为什么转动视角容易从 120fps 暴跌到 30~40fps？（旋转满帧 5 条铁律）
1. **烘焙倍率必须与 Retina 物理 `SCALE` 解耦**：切忌按物理屏幕缩放（如 `SCALE = 12`）去烘焙巨图！改为固定黄金倍率 **`BAKE_SCALE = 2.5`**，单张烘焙面积直降 **18 倍**，画质更有统一像素味，且**滚轮缩放不清空缓存**。
2. **严禁烘焙时频繁新建/销毁临时 `<canvas>`**：全局仅复用 2 张临时画布（`scratchRaw` / `scratchSil`）完成切片与描边合成；LRU 淘汰的缓存画布回收到 `canvasPool` 对象池，彻底消除 GC 卡顿。
3. **自亮体素 Z 遮挡必须从 `minGlowZ` 开始 + 对称部件共享角度槽**：跳过首个自亮层以下的所有无用 `destination-out`；旋转对称部件（发团、圆珠、对称石柱）标 `symDeg = 90` 共享缓存。
4. **消除全屏中间层 Overdraw**：静态天空背景预渲染到 `bgc`；地面、投影与水面动态涟漪全画在 **2× 小地表缓冲**（面积仅全屏的 `1/30`）后再 1 次旋转贴图到 `dctx`；缓存模式直接将烘焙精灵或 `actorBuf` 画到 `dctx`，彻底省掉全屏 `mc / gc / oc` 的清屏与拷贝带宽。
5. **在 1/4 小画布上执行「真·降采样模糊」**：切忌在全屏主画布 `dctx` 上设置 `dctx.filter = blur(...)` 去画 1/4 小图 `ec`（浏览器仍会放大到全屏再做高斯模糊！）。必须单独建一张 1/4 尺寸的模糊缓冲 `eb`，在 **`ebctx` 上执行 `filter = blur`**，再让 `dctx.filter = 'none'` 直接 `screen` 放大贴回主画布，模糊开销真降 **16 倍**。

### 1.4 2.5D 深度遮挡、自亮层 Z 裁切与真·1/4 降采样柔化
分离自亮层（单独画到 `ec` 再 `screen` 叠亮）极易产生**「X 光穿墙透视」**和**全屏 `ctx.filter = blur` 掉帧**两大问题。标准解法：

1. **部件内部自亮自遮挡**：在自下而上（`z = 0..H-1`）烘焙或绘制切片时，从 `z >= minGlowZ` 起，每升一层先用当前层**不透明实心切片**对自亮层执行 `globalCompositeOperation = 'destination-out'`，再以 `source-over` 绘制当前层自亮像素。
2. **跨部件与跨物体自亮遮挡**：在 `actorBuf` 内部拼合部件时以及在主场景按远→近（`ry` 升序）绘制不同角色时，先用前景不透明剪影对 `actorGlow` / `ec` 执行 `destination-out`，再把前景自身的自亮层叠入。
3. **真·1/4 降采样柔化**：`ec` 与 `eb` 均设为显示画布的 **`1/4 × 1/4`**；先在 `ebctx` 执行 `blur` 将 `ec` 模糊画入 `eb`，再在 `dctx`（`filter = 'none'`）用 `screen` 放大叠加 `eb` 与清晰核心 `ec`。
4. **DPR 逻辑一致性**：按 CSS 逻辑高度算基准缩放再乘 `Math.min(2, devicePixelRatio)`，确保 1x/2x 屏幕下滚轮缩放步幅、视野大小与外轮廓视觉粗细完全一致。

## 2. 色彩、明暗与接地感设计规范（7 条铁律）

像素堆叠切片不依赖实时 3D 光照，立体感完全由程序化着色与落地投影决定。严格遵守以下 7 条铁律：

1. **明暗只分上下，严禁画左右方向明暗**
   - 物体会 360° 旋转，切片里一旦画了“左亮右暗”，转到背面立刻穿帮。
   - 所有明暗仅由 `z` 高度、朝上露边（`topEmpty`）、朝下底沿（`botEmpty`）与腔体遮蔽驱动。
2. **控色精简（≤ 48 色）+ 高对比 3 档色阶**
   - 单材质优先采用 **3 档高对比色阶（暗面 / 主色 / 露边亮色）**；过多相近灰阶在低分辨率下会揉糊轮廓。
3. **自亮色必须与普通色物理隔离，并支持状态切换**
   - 非自亮色键禁止与自亮色键共用同一十六进制色值，防止误发亮。
4. **精细体素着色：露边提亮 + 上方 3×3 腔体 AO + 白名单部件暗缝 + 局部高度**
   - **露边提亮**：`z + 1` 为空的像素（`topEmpty`）提亮一档；球顶类形态避免每层全涂最亮造成同心条纹。
   - **白名单部件接缝（Crease AO）**：给体素记录 `partId`，不同部件相接处压暗一档切出清晰缝隙，但须配置**免暗缝白名单**（如 `eye:head`、`tridentCore:trident`、`torso:head`、`torso:arm`、`tail:tailFin`），防止细小部件或眼眶周围整体发黑。
   - **上方 3×3 腔体 AO**：检查 `z + 1` 层周围 8 邻域实心遮蔽数，自然压暗真实凹槽。
   - **部件局部归一化高度**：统计每个 `partId` 的 `[minZ, maxZ]`，让柱体与悬空部件自带底部压暗过渡。
5. **厚度 ≥ 2 格 + `despeckle()` 孤立像素清理**
   - 细结构（武器柄、四肢、尾巴、鳍骨、翼骨）半径应 `≥ 1.05~1.25`（截面 ≥ 2×2 格），避免斜角旋转碎成闪烁噪点；薄鳍/翅膜用 `paintFinTri(..., halfThick ≥ 1.05)`。
   - 建模完成后统一执行 `despeckle(protectedParts)` 清理 3D 孤立单像素（白名单保护眼睛、武器亮核等刻意细节）。
6. **相邻层平滑过渡，交界一律 `smin` 融合**
   - 躯干接脖子、肩胸过渡等有机衔接严禁直角硬拼，一律使用平滑并集 `smin(a, b, k)`。
7. **双层接地投影与前景环境交互（消除「贴纸漂浮感」）**
   - **陆地物体**：离线足迹剪影投射影（`footShadow`）+ 紧贴落脚点的深色接触影（飞行高度抬升时投影按高度同步缩小淡化）。
   - **水生/浸水生物**：在池底画水下折射深色体影 + 水面涟漪/V 形尾流，并在**角色绘制之后**于 `dctx` 叠加**前景破水白沫弧与半透水罩**，把身体真正“嵌”进水里（见第 4.4 节）。

## 3. 高性能体素建模与零重建模换色（纯 JS 零外部依赖）

### 3.1 第 0 步：先写「模块化部件空间坐标预算表（Part Budget）」
写代码前必须列出每个部件的**盒尺寸 `W × D × H`、局部锚点、挂接坐标与防穿模净空**（例如裙摆底沿 Z、尾根前两节下延 Z、肩部/颈部世界坐标），确认相邻部件既无缝贴合又互不穿模再编码。

### 3.2 核心性能优化：`Uint8Array` 索引网格 + 部件级 AABB 局部扫描
- `grid = new Uint8Array(w * d * h)`（`0` 为空、`1..48` 为色表 ID、`128 + matId` 为待着色材质标记）与 `parts = new Uint8Array(w * d * h)`；
- 提供 `fillAABB(...)`、`paintCapsule(...)`、`paintEllipsoid(...)`、`paintFinTri(...)`，每个部件**只遍历自身最小包围盒**；
- 拆成小型模块化骨骼部件后，整套角色（14~22 个小部件）构建总耗时通常只需 **`15~30ms`**（比整块 8 帧方案快 3~30 倍）。

### 3.3 零依赖 PNG 导出与零重建模一键换色（`SKINS`）
1. `toStripAsset()` 保留原始索引数组 `grid: this.grid`；
2. `SKINS` 皮肤表仅覆写语义色槽（如 `tailDark/Mid/Hi`、`emissiveMid/Hot/Core`）并配套 **`fx` 特效色表**（投射物、涟漪、尾流、冲击波、地面残留、天空背景）；
3. 切色时调用 `recolorAsset(asset, rgbaTable)` 按索引重刷全部部件长条 `ImageData`（耗时 **`0.2~0.8ms`，0ms 重建模**），再仅清理该角色在 `spriteCache` 中的条目并回收至 `canvasPool`（不误清靶桩/环境缓存）。

## 4. v3 核心升级：模块化骨骼运动学 + 局部整体轮廓 + 物种生态（重点！）

### 4.1 告别 8 帧僵硬翻页：为什么 `snake` 和 `siren` 活了起来？
过去将整只怪物烘焙成 8 帧大体积翻页（`Math.floor(t * 7) % 8`）有三大通病：① 待机只有 6~8fps 抽搐感；② 技能演出时角色被迫冻在单帧静态图上；③ 只能原地平移或浮空转圈，毫无生物质感。

**v3 标准做法**：把角色拆分为轻量模块化小部件，在 `tick(dt)` 中以 **60~120fps 连续运动学**实时驱动各部件的 `(x, y, z, yaw)`，并复用 `BAKE_SCALE = 2.5` 定倍角度缓存：
- 所有待机呼吸、摆尾、振翅、飘发、武器微晃、移动与技能起手/收招全程连续过渡（指数平滑 `k = 1 - Math.exp(-dt * speed)`），**零跳帧、零技能僵死**；
- 小部件建模极快（`15~30ms`），且因为共享小部件角度缓存，120fps 满帧无压力。

### 4.2 关键渲染铁律：何时「单节描边」 vs 何时「局部整体轮廓 `actorBuf`」？
| 描边策略 | 适用生物 | 做法与效果 |
|---|---|---|
| **单部件各自描边**（见 `snake/index.html`） | 强鳞节/甲壳/链节生物（魔蛇、蜈蚣、机械链） | 各节自带 1px 黑边反而强化一节节鳞片层次 |
| **局部缓冲 `actorBuf` 整体 1px 外轮廓（见 `siren/index.html`，绝大多数生物首选！）** | 人形、水生、飞龙、妖精、蝙蝠、哥布林、鱼人、史莱姆 | 所有小部件按 `wantOutline = false` 裸图缓存 → 每帧在紧凑局部缓冲 `actorRaw`（如 `240×246`，仅全屏面积 `1/80`）内按 3D 深度拼合拼成完整角色 → 对 `actorRaw` 做 **1 次** `source-in` 1px 整体外轮廓得到 `actorOut` → 单次贴到 `dctx`。**内部光滑融合零拼装玩具黑缝、外圈轮廓锐利统一、角色与靶桩轮廓清晰分离，且单帧仍仅 `0.3~0.4ms`（120fps）！** |

> **注意 `actorBuf` 空间预留**：`ACTOR_W × ACTOR_H` 与锚点 `(ACTOR_AX, ACTOR_AY)` 必须按**最高技能抬手（如高举武器/跃起砸地）与最远摆尾/展翼半径**留足边距，避免极值动作在 360° 任一角度被画布边界裁切。

### 4.3 四大生物骨骼原型速查
| 原型 | 代表魔物 | 部件拆分与核心运动学 |
|---|---|---|
| **A. 链式脊柱型** | 魔蛇（标杆 `snake/`）、长尾部位 | `head` + `jaw` + 多档粗细体节 + `tailTip`；用行进正弦波 + 2 次迭代 Follow-the-Leader 距离约束 `relaxChain(chain, segLen)` + 指数平滑驱动 |
| **B. 人形 / 水陆混合型** | 美人鱼（标杆 `siren/`）、哥布林、鱼人怪 | `torso` + `head` + `armL/armR` + `weapon` + 下肢（`legL/legR` 或多节尾链）+ 附属飘带/长发/披风；支持**常驻站姿与俯身冲刺/泳姿专用上身部件切换**（通过 `pitchPt` 绕 X 轴倾倒 SDF 精确生成，绝不硬拉伸 2D 图） |
| **C. 振翅飞行型** | 飞龙（双形态）、妖精仙子、魔物蝙蝠 | `torso` + `neck/head`（多节龙颈可独立摆头）+ `wingL/wingR`（多姿态或肩部枢轴扇动，配翼根锁定）+ 尾链/爪；**升沉相位滞后于拍翅下压**（下拍瞬间产生升力抬升！），盘旋时身体顺向心方向微微压弯与领头偏航 |
| **D. 弹性软体型** | 史莱姆 | 外层果冻主体（支持多档压扁/拉长态或实时 `scaleX/scaleY` 体积守恒 Squash & Stretch：`rx * ry * rz ≈ 1`）+ 独立漂浮内核/气泡/眼神/头饰部件（用**二阶弹簧阻尼**滞后跟随主体移动与落地回弹！） |

### 4.4 五大骨骼化防坑铁律（来自 `snake` & `siren` 实机踩坑总结）
1. **防穿模净空预算 + 层序偏置（`bias`）**：
   - 凡有裙摆、披风、甲片包覆肢体/尾根的部位，先在体素坐标上留出物理净空（如高腰水裙底沿抬高至 `z ≥ 3`，尾根第 `0~1` 节先垂直下延离开裙沿再向后弯曲）；
   - 在 3D 深度排序公式 `depth = ry + lift * 0.08 + bias` 中，对被包覆的根节给微负偏置（如 `-1.4`）、外罩饰件给微正偏置（如 `+0.8`）；
   - 用 Node 脚本遍历整个动作周期，**自动断言相邻互斥部件的最小带符号距离 `> 0`**。
2. **关节旋转枢轴锁死（彻底消除大幅摆动时的 1~2px 挤捏缝）**：
   - 当尾鳍、翅膀、武器、盾牌等部件的真实关节不在体素盒中心 `(0, 0)`，而是位于局部 `(px, py)` 时，直接放在 `(jointX, jointY)` 并绕中心旋转会导致关节处甩开脱节！
   - **标准公式**：用 `localToWorldXY(jointX, jointY, partYaw, -px, -py)` 计算部件摆放中心，让旋转严格锁死在真实关节轴心上。
3. **物种真实移动规律 + 双生态常驻模式（杜绝「浮空平移物体」）**：
   - 每个魔物必须配备 **2 套常驻生态**（原地鲜活待机 + 绕台物种巡游，快捷键 `S` 切换）；
   - 移动绝不能只是“竖直静止模型绕圆匀速平移”！必须还原生物推进机制：
     - **水生（人鱼/鱼人）**：俯身前倾流线泳姿 + **脉冲式摆尾加速-滑行（Burst-and-Glide）** + 周期潜浮破水 + 双线 V 形尾迹（Kelvin Wake）；
     - **飞行（飞龙/妖精/蝙蝠）**：强下拍提速与滑翔周期 + 高度起伏与盘旋偏航 + 翼尖气流粒子/洒粉；
     - **陆行双足（哥布林/鱼人陆走）**：高节奏碎步/跳跃（脚步落地瞬间出尘土 + 身体上下弹跳 + 武器防抖后拖 + 转向预瞄）；
     - **软体（史莱姆）**：蓄力压扁 → 弹射拉长离地 → 落地二次果冻颤动回弹 + 黏液水渍。
4. **环境前景覆盖层（禁止用 2D 水平 `rect()` 裁切宽精灵！）**：
   - **反面教训**：在俯视 0.6 倾角下，对宽体素精灵（如 `22×22` 尾鳍）用 2D 水平 `clip rect` 按中心水面线裁切，会把仍在水平面以上的近端边缘一刀劈平并描出难看的水平黑线！
   - **正确解法**：浸水/半潜部件按真实 3D 高度平滑柔和透明（`alpha = 1 - submerge * 0.42`），并在**角色绘制完成之后**往 `dctx` 叠加**前景破水白沫弧 / 半透浅水罩**（陆地奔跑则叠加前景扬尘/草叶），视觉上瞬间把生物“嵌”进水体或地表。同时水池底面避免杂乱大白斑和机械通长直线，让动态涟漪与 V 形尾流成为主角。
5. **技能全程骨骼连续表演 + 紧凑 HUD**：
   - 所有技能阶段（蓄力、突进/挥击、命中爆发、收招）全程驱动骨骼参数插值，绝不切回静态僵死帧；
   - 顶部控制面板保持紧凑（`max-width ≤ 420px`），并控制巡游半径，保证角色在 `1280×800` 常用窗口下绝不钻到 UI 面板后方。

### 4.5 精确 2-Bone 平面解析 IK 与最短角复位
- 涉及双腿踩踏、行走步态或连杆时，用余弦定理 `solveIK2D(hy, hz, ty, tz, L1, L2, bendDir)` 严格保持骨长恒定（误差 `< 0.01`）。
- 360° 查看器点「重置视角」前，将 `th` 规整到 `[thTarget - π, thTarget + π]` 最短角区间，防止转多圈后疯狂倒转。

## 5. 零依赖「量化校验 → 浏览器实机审片 → 迭代打磨」闭环

AI **绝不能盲写代码直接交货**。每次改造或新建魔物必须跑通以下闭环：

### 5.1 第一道关：Node 自动化量化校验（1 秒跑完）
1. **JS 语法与禁用词检查**：`new Function(script)` 校验零语法错；检查所有界面文本/皮肤名/技能名不含项目禁用字（`灯、烬、影、夜、魂、噬、幽、渊、星、光` 及 `守×者 / ×之×`）。
2. **调色板与体素合规**：所有皮肤色表 `≤ 48` 色、0 重色、自亮色隔离、0 未着色体素（`id >= MAT_BASE`）、0 3D 孤立碎点、整套部件总建模耗时 `< 40ms`。
3. **关键锚点可见性射线断言**：从双眼、武器亮核等关键部位沿 `+Y` 与 `0.6` 俯视斜线扫描，断言遮挡体素数 = `0`。
4. **关节衔接与防穿模几何断言（v3 新增！）**：
   - 验证俯身/站立态下颈口、肩位、手握武器、翼根等接缝世界坐标误差 `< 1.0` 格；
   - 遍历完整动作周期，验证易穿模部件（如裙摆 vs 尾链、翼面 vs 躯干）最小带符号净空 `> 0`。

### 5.2 第二道关：浏览器实机多视角审片 + 亲自看图
- 启动本地静态服务打开页面，确认 **Console 0 报错**；
- 实测默认待机（正斜、正侧、背斜 3 角度近景）、巡游模式（`S` 键观察至少 1.5s 移动轨迹与尾迹/烟尘）、全部皮肤零重建模切色、全部技能连续骨骼表演、自动旋转帧率（`60~120fps`，单帧 `< 1.0ms`）；
- **必须用看图工具亲自复查实际渲染截图**，确认：① 零穿模；② 关节无脱节/无 1px 挤捏缝；③ `actorBuf` 整体外轮廓干净无内部碎线且高举动作零裁边；④ 物种移动方式真实自然、彻底无“浮空平移感”；⑤ HUD 不挡角色。发现任何瑕疵立刻修完复测，再提交。

### 5.3 典型实测缺陷与修复案例库
| 实测缺陷 | 根因 | 修复方案 |
|---|---|---|
| 待机动作抽搐生硬、放技能时模型冻成木头人 | 8 帧大块翻页（6.5~8fps）+ 技能锁单帧 | 拆分为模块化小部件 + 120fps 连续运动学骨骼 + 技能全程骨骼插值（见 `snake/`、`siren/`） |
| 拆成骨骼部件后满身内部黑线，像拼装玩具 | 对每个部件各自执行了 1px 描边 | 除强鳞节蛇类外，改用 `actorBuf` 裸图深度拼合后再做 **1 次** 整体外轮廓（单帧 `0.3~0.4ms`） |
| 美人鱼尾巴与腰部裙摆穿模 | 裙摆垂得太低 + 尾根第 0~1 节立刻向后折入裙瓣区间 | 抬高高腰裙底沿（`z ≥ 3`），尾根前两节先垂直下延离开裙沿，加 `bias` 排序偏置并用 Node 断言净空 `> 0` |
| 鱼尾大幅摆动时末端与扇形尾鳍出现 1~2px 挤捏缝 | `tailFin` 锚点在盒中心而非鳍根 `pWr`，旋转时鳍根被甩离尾尖 | 用 `localToWorldXY(tip.x, tip.y, finYaw, 0, -2.6)` 把旋转枢轴锁死在尾尖关节 |
| 水生生物看起来像悬空平移物体，没有鱼类质感 | 竖直姿态匀速绕圈 + 全部画在水面之上无前景遮挡 + 水底大白斑干扰 | 切换前倾 56° 流线泳姿 + 脉冲摆尾加速-滑行 + 波浪潜浮 + 双线 V 形尾流 + **角色后绘前景破水白沫弧** + 清理水底杂斑 |
| 用 2D 水平 `rect()` 裁切浸水部位把宽尾鳍劈出一刀平黑边 | 0.6 俯视下高于水面的近端像素在屏幕 Y 上落于中心水面线下方 | 取消 2D 矩形硬裁，改按 3D 浸水深度柔化透明 + 前景水面覆盖弧 |
| 静止 120fps，一拖动/旋转视角立刻掉到 30~40fps | 按 Retina 物理 `SCALE` 烘焙巨图 + 全屏 `dctx.filter=blur` + 全屏中间层 Overdraw | 固定 `BAKE_SCALE=2.5` + 复用 2 张 scratch 与对象池 + `minGlowZ` 剪枝 + 真 1/4 `ebctx` 模糊 + 2× 小地表缓冲直绘 `dctx` |
| 高分斜角下斜管/翅膀现百叶窗层间黑缝 | `HS (0.8) > TILT (0.6)` 错位层露出 `0.2 × SCALE` 缝隙 | 烘焙时加 `1px` 半步压实绘制 `yy + BAKE_HALF` |
| 眼睛或武器亮核在默认俯视下被挡住 | 没列空间坐标预算表，上方眉弓/冠饰/饰板在 0.6 倾角下遮挡 | 动工前写预算表，并用 `+Y` 与 `0.6` 俯视射线脚本断言遮挡数 = `0` |

{

  "outlineMode": "actorUnified",
  "strip": "unit_example_part.png",
  "w": 18,
  "d": 14,
  "h": 15,
  "lift": 0,
  "footRadius": 12,

  "centerZ": 20,

- `footRadius`：探索地图碰撞与接地接触影半径；

- `centerZ`：伤害飘字、受击特效与死亡消散粒子的标准锚点高度；
- `tintSlots`：同骨架不同变体配色及受击闪白/破盾高亮的查表槽位。
