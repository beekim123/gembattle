# 像素堆叠工坊

纯原生 JS + Canvas 2D、零依赖的像素堆叠（Sprite Stacking）制作台。做的东西不止怪物，以后还有 **NPC、建筑、场景环境**，都在这里预览、调参、多只同屏试跑、压测、导出。

> **接手先看**：
> 1. 本文件（怎么开、目录、怎么加新东西、性能规矩）；
> 2. `文档/生物图鉴与逐只精制规划.md`：**怪物制作清单**（42 只怪，状态 `[ ]` 待做 / `[~]` 初版 / `[x]` 精制完成），工坊左栏怪物清单从此生成；
> 3. `文档/全品类模板规划与参考.md`：**全品类模板母表**（5 大类 × 29 种基础模板，含怪物骨架类型、NPC、建筑、场景摆件、动态载体），工坊「按类型分类」与 NPC/建筑/场景待做模板均从此同步；
> 4. `文档/骨骼化改造交接与经验.md`：逐只精制时的防糊、防穿模经验；
> 5. `文档/性能与流畅度-2026-11-23.md`：渲染器为什么这么写、实测数字、还没做的流畅度改进；
> 6. **生态设计**：顶栏「生态总览」（`ecology.html`）看生态地图、每个生境的食物网、每只生物的设计；数据在 `文档/生态设计数据.js`（改设计改这一份），规矩在 `文档/异世界生物类型扩展草案-M18至M35.md`。

## 怎么打开

在本目录起一个静态服务（仓库根目录 `.claude/launch.json` 里的 `workshop` 就是这条）：

```bash
python3 -m http.server 8127
```

然后开 `http://localhost:8127/`。直接双击 `index.html` 也能用。

网址参数（可叠加）：`?focus=slime_jelly`（打开就选中这只）、`&hab=swamp`（生境地台）、`&bench=1`（打开就跑一轮压测）。

## 加一只新怪

1. 在 `creatures/` 新建脚本。**文件名和 id 用清单编号的前缀**，工坊会自动对上清单：`天=sky 水=water 海=sea 地=earth 树=tree 沙=sand 洞=cave 泽=marsh 特=special`，比如 `天1` 写成 `sky1_danghu.js`、id `sky1_danghu`。不想用前缀，就在 Def 里写 `code: '天1'`。
2. 写 Def，末尾 `PW.Creatures.push(Def)`。照现有的抄，最省事的是 `creatures/slime.js`（结构最完整）：
   - 必须有：`id`、`name`、`createInstance(makeCanvas, opts)`；
   - 实例要有：`parts`（部件表）、`state`（至少 `x y z yaw`）、`update(dt, time, params, habitat, vfx, eco)`、`buildPartList(habitat)`、`reset(x, y, yaw)`；有换色就加 `applySkin(i)` 和 `curSkin`；
   - 可选：`code`、`status`（`draft` 初版 / `done` 精制完成）、`actions`（展示动作，见下）、`skins`、`defaultHabitat`、`tag`、`summary`、`blocks`、`soulHabit`、`defaultParams`。
3. `index.html` 的「怪物」那段加一行 `<script src="creatures/xxx.js"></script>`。
4. 改 `文档/生物图鉴与逐只精制规划.md` 里这一条的状态（`[ ]` → `[~]` → `[x]`），然后在本目录跑：

```bash
node tools/sync-catalog.js
```

刷新页面，左栏这一条就从「待做」变成「初版」，能点了。

`buildPartList` 每帧返回一组要画的部件，每个是 `{ asset, x, y, lift, ro, bias, opacity, submerge, symDeg }`：位置（格）、离地高度、朝向（弧度）、深度微调、设计上的半透明、浸水程度、对称角度。渲染器按深度排序、烘焙、描边，生物脚本不用管。

## 加技能展示（动作）

现在每只怪只有「自由巡游」「原地待机」两个动作。以后加技能展示，**一个技能一条**，写进 Def 的 `actions`：

```js
actions: [
  { id: 'patrol', name: '自由巡游', loop: true,  status: 'draft' },
  { id: 'idle',   name: '原地待机', loop: true,  status: 'draft' },
  { id: 'skill_charge', name: '蓄力冲撞', loop: false, duration: 2.4, status: 'todo' }
]
```

- 右栏「展示动作」会列出来，带状态；点一条就在焦点身上放，「台上全部用这个动作」让台上所有有这个动作的一起放；
- 脚本的 `update()` 从第 6 个参数 `eco` 读 `eco.action`（现在在放哪个动作的 id）和 `eco.actionTime`（放了几秒）；
- `loop: false` 的动作放完 `duration` 秒，自动回到第一个动作；
- 旧脚本只认 `eco.patrol`（巡游 = true、待机 = false），工坊照旧给，不用改。

## 加 NPC / 建筑 / 场景摆件

跟怪一样写 Def 和实例，只是登记换成 `PW.Assets.register(Def, 'npc')`（或 `'building'`、`'scene'`），`index.html` 对应那段加一行。各自的注意事项看 `npc/README.md`、`buildings/README.md`、`scenes/README.md`。

## 画质和性能的规矩（渲染器 2026-11-23 换过一版）

- **同屏数量**：2560×1440 下，同屏 36 只每帧约 4.7ms（约 210fps），24 只 3ms。原来 3 只就 2.2ms、24 只 55ms。细节和测法见 `文档/性能与流畅度-2026-11-23.md`。
- **贴图总量别超过 32MB**：Chrome 一帧里用到的贴图超过 32MB 左右，GPU 会突然慢 7~35 倍（跟画布多大无关）。所以烘焙图集封顶 28MB（右栏能改），满了按最久没用的页淘汰，正在用的会当场重画、不丢帧。新做的东西别另开整屏大小的离屏画布。
- **清晰**：画面放大倍数取整数（1 个美术像素 = 整数个屏幕像素），部件按屏幕像素摆放，所以不糊、移动也细。**常态别用 `scaleX / scaleY` 拉伸**（最近邻拉伸会抖），呼吸感用位移和姿态做。
- **半透明分两种**：设计上就是半透明的（史莱姆的果冻壳）写 `opacity`；进水写 `submerge`，水域里会染成水色、不变透明（不再叠出深浅斑）。
- **左右对称的部件自动只烘一半角度**，另一半翻过来画；不用管。
- **换色**：调用 `recolorAsset` 就行，缓存会自己作废，不用手动清。
- **同种多只共用部件**：工坊放第二只同种怪时，体素模型和烘焙图共用，同屏 30 只史莱姆也只占一只的贴图。
- **改了渲染器**，看一眼性能浮层，再跑一遍右栏「跑一轮压测」或 `?bench=1`，跟上面的数字对一下。窗口在后台或被挡住时浏览器会限帧，浮层会写「浏览器限帧」，那时的数字别当真。

## 渲染方式

- **游戏缓存**（默认，游戏里也用这个）：部件按角度烘焙进图集，每帧只贴图；
- **高清逐层**：每帧逐层实时画，最清晰、最慢，用来对照烘焙版有没有走样；
- **复古低分**：低分辨率逐层画再放大，看老派像素效果。
